### 접근 방식 : 1. 백트래킹 (DFS + 가지치기)
- 왜 이 방식으로 풀었나?
  - 그리디로 큰 색종이부터 덮으면 최적해가 안 나오는 반례가 있어서 완전 탐색 기반 백트래킹 선택
  - (0, 0)부터 순회하다가 1을 만나면 1x1부터 5x5까지 크기별로 붙일 수 있는지 검사
  - 각 크기별 5장 제한 확인하고 붙인 뒤(0으로 변경), 다음 칸 탐색 후 다시 원복(1로 복구)
  - 현재 사용한 색종이 수가 이미 구한 최솟값(ans) 이상이면 즉시 return으로 가지치기
- 시간복잡도, 공간복잡도 관점에서의 성능 비교 
  - 시간복잡도: O(5^K) (종이 5장 제한과 가지치기로 실제 탐색 공간은 크게 축소)
  - 공간복잡도: O(1) (10x10 격자와 최대 100 깊이의 재귀 호출)
  - 메모리: 고정 배열 사용으로 수십 MB 내외, 0.3초 내외 통과

### 회고 
- 몇 번만에 성공했는지 : 2번
- 잘한 점 : 색종이 검사와 붙이기/떼기 로직을 함수로 깔끔하게 나누고 가지치기 적용한 점
- 개선할 점 :
  - x == 10일 때 y+1 재귀 호출 후 return을 빼먹어서 IndexError 발생했던 점 주의하기
  - 색종이 크기를 5부터 1로 거꾸로 돌리면 큰 걸 먼저 채워서 최솟값을 더 빨리 찾을 수 있음
