### 문제 설명

- 문제 URL : [롤케이크 자르기](https://school.programmers.co.kr/learn/courses/30/lessons/132265)
- 풀이일 : 2026-10-29
- 롤케이크를 한 번 잘랐을 때 양쪽에 올라간 토핑의 종류 수가 같아지는 경우를 구하는 문제.

### 접근 방식 : 해시맵과 집합

처음에는 자르는 위치마다 오른쪽 토핑을 끝까지 다시 확인했다. 왼쪽과 오른쪽의 종류 수를 비교하는 방식은 이해하기 쉬웠지만, 오른쪽을 계속 다시 세다 보니 입력이 커지면 오래 걸린다.

- 먼저 오른쪽에 있는 토핑별 개수를 해시맵에 저장한다.
- 자르는 위치를 한 칸씩 옮기면서 현재 토핑을 왼쪽 집합에 넣는다.
- 오른쪽에서 해당 토핑이 한 개 남아 있었다면 맵에서 제거하고, 그보다 많이 남아 있었다면 개수를 하나 줄인다.
- 왼쪽 집합의 크기와 오른쪽 맵의 크기가 같을 때마다 경우의 수를 더한다.

오른쪽 토핑의 개수를 관리하는 게 포인트다. 토핑이 더 이상 남지 않았을 때만 종류 수가 줄어들기 때문에, 집합 하나만으로는 어떤 시점에 제거할지 알기 어렵다.

### 복잡도

- N은 토핑 배열의 길이, K는 서로 다른 토핑의 종류 수.
- 시간 : 평균 O(N). 처음에 개수를 세고, 자르는 위치를 한 번씩 확인한다. 해시 연산은 평균 O(1)로 본다.
- 공간 : O(K). 왼쪽 집합과 오른쪽 맵에 토핑 종류를 저장한다.

### 회고

처음에는 오른쪽 개수가 0인지 확인한 뒤에 제거하도록 작성했다. 하지만 마지막 한 개를 옮기는 순간에는 아직 개수가 1이어서, 0으로 바뀐 항목이 맵에 그대로 남았다. 맵의 크기가 실제 종류 수와 달라지는 이유였다.

현재 개수가 1일 때 바로 제거하도록 바꾸니 남은 토핑 종류를 올바르게 셀 수 있었다. 매 위치에서 오른쪽 전체를 다시 만드는 대신 바뀐 토핑 하나만 갱신하면 된다는 점을 기억해두면 좋겠다.
