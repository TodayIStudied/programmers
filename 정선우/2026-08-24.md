### 접근 방식 : 상태 배열 + 그리디
- 왜 이 방식으로 풀었나?
  - 처음에는 `lost` 배열에서 학생을 찾고 직접 제외하는 방식을 생각했다.
  - 하지만 학생별 체육복 상태를 `0 / 1 / 2`로 관리하면 현재 상황을 훨씬 단순하게 표현할 수 있었다.
  - 학생을 앞에서부터 확인하면서 여벌이 있는 학생이 체육복이 없는 앞사람에게 먼저 빌려주는 방식으로 처리했다.
  - 앞사람은 현재 지나치면 이후에 체육복을 받을 기회가 사라질 수 있지만, 뒷사람은 뒤 학생에게 받을 가능성이 남아 있기 때문에 앞사람을 우선했다.

```java
class Solution {
    public int solution(int n, int[] lost, int[] reserve) {

        int[] clothes = new int[n + 1];

        for (int i = 1; i <= n; i++) {
            clothes[i] = 1;
        }

        for (int student : lost) {
            clothes[student]--;
        }

        for (int student : reserve) {
            clothes[student]++;
        }

        for (int i = 1; i <= n; i++) {

            if (clothes[i] == 2) {

                if (i > 1 && clothes[i - 1] == 0) {
                    clothes[i]--;
                    clothes[i - 1]++;
                }
                else if (i < n && clothes[i + 1] == 0) {
                    clothes[i]--;
                    clothes[i + 1]++;
                }
            }
        }

        int answer = 0;

        for (int i = 1; i <= n; i++) {
            if (clothes[i] >= 1) {
                answer++;
            }
        }

        return answer;
    }
}
```

- 시간복잡도
  - 학생 수를 기준으로 배열을 순회하므로 `O(N)`

### 새롭게 알게 된 점
- 그리디(Greedy) :  **현재의 선택이 이후 선택지를 망치지 않도록 하나씩 결정하는 방식**이라는 것을 알게 되었다.
- 학생별 상태를 하나의 배열로 관리하면 문제를 단순화할 수 있었다.

```text
0 → 체육복 없음
1 → 정상
2 → 여벌 있음
```

- `lost`와 `reserve`가 겹치는 학생도 별도 예외처리 없이 자연스럽게 해결된다.

```text
기본 1
도난 -1
여벌 +1
→ 1
```

### 회고
- 잘한 점 : 여벌 학생이 앞/뒤 학생에게 빌려준다는 구조와 그리디 방식의 흐름을 이해했다.
- 헷갈렸던 점 : 왜 무조건 앞사람을 먼저 확인해야 하는지가 처음에는 이해되지 않았다.
- 기억할 점 : 그리디 문제에서는 단순히 현재 선택만 볼 것이 아니라, **이 선택을 했을 때 이후 선택지가 어떻게 남는지** 생각해보기.
