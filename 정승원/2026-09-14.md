### 문제 설명
- 문제명: Carry 피하기 2
- 풀이 URL: [Carry 피하기 2 — 내 풀이 코드](https://github.com/HappyPotatohappy/CodingTest/blob/main/trail2/Carry%20피하기%202/escaping-carry-2.py)
- 사용 언어: Python
- 서로 다른 N개의 수 중에서 정확히 3개를 골라 더할 때, 어느 자리에서도 carry(받아올림)가 발생하지 않는 조합 중 합의 최댓값을 출력한다.
- carry는 각 자릿수끼리 더한 값이 10 이상이 되는 것을 말한다. 일의 자리에서 괜찮더라도 십의 자리에서 넘치면 불가능한 조합이다.
- 가능한 조합이 하나도 없으면 `-1`을 출력한다.
- 제약: `3 ≤ N ≤ 20`, `1 ≤ a_i ≤ 10000`, 모든 수는 서로 다르다.

### 접근 방식 : 1. 3중 for문 완전탐색 + 자릿수 단위 carry 검사
- 왜 이 방식으로 풀었나?
  - N이 최대 20이므로 3개를 고르는 모든 경우를 다 확인해도 N³ = 8,000번에 불과하다. 완전탐색으로 충분하다.
  - 3중 `for`문으로 인덱스 `(i, j, k)`를 고르고, `i == j`, `j == k`, `k == i`인 경우는 `continue`로 걸러서 "서로 다른 3개"라는 조건을 지킨다.
  - 각 조합에 대해 `check(num1, num2, num3)`로 carry 발생 여부를 판정하고, 통과한 조합의 합으로 `ans`를 갱신한다.
  - `ans`를 `-1`로 초기화했으므로 통과한 조합이 하나도 없으면 별도 처리 없이 그대로 `-1`이 출력된다.

- carry를 판정하는 방법 -> 이것이 핵심.
  - `nte(num)`은 수를 문자열로 바꿔 자릿수 리스트를 만든 뒤 `reverse()`한다. 인덱스 0이 일의 자리, 1이 십의 자리가 되도록 맞추기 위해서다.
  - 세 수의 자릿수가 다르면 비교 위치가 어긋나므로, 가장 긴 길이 `mx`만큼 `[0] * mx` 배열을 만들고 각 수의 자릿수를 앞에서부터 채운다. 남는 높은 자리는 0으로 채워지는 셈이다.
  - `zip(n1, n2, n3)`로 같은 자리의 숫자 세 개를 한 번에 꺼내 `i + j + k >= 10`이면 즉시 `0`을 반환한다. 모든 자리를 통과하면 `1`을 반환한다.
  - 세 자릿수의 합이 모든 자리에서 9 이하이면 어느 자리에서도 받아올림이 생기지 않고, 따라서 다음 자리로 전달되는 값도 없다. 자리별 합만 검사하면 충분한 이유다.

- 생각해볼 수 있는 다른 방법 -> 검사 방식이 다를 뿐 탐색량은 같다.
  - 자릿수 합 트릭: 덧셈에서 carry가 한 번 발생할 때마다 결과의 자릿수 합이 9씩 줄어든다. 따라서 `digitsum(a) + digitsum(b) + digitsum(c) == digitsum(a + b + c)`이면 carry가 없다. 리스트를 만들거나 길이를 맞출 필요가 없어 코드는 짧아지지만, 판정 비용은 같은 O(D)다.
  - 정렬 후 가지치기: 수를 내림차순으로 정렬하고 `arr[i] + arr[j] + arr[k]`가 현재 `ans` 이하가 되는 순간 안쪽 루프를 `break`한다. N이 20이라 실익이 거의 없어 사용하지 않았다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(N³ × D)** — D는 자릿수(최대 5)
    - 인덱스 3중 루프가 N³번 돌고, 각 조합마다 `check`에서 자릿수 리스트 생성과 `zip` 순회에 O(D)가 든다.
    - N = 20, D = 5여도 4만 번 안팎의 연산이라 시간 제한(1초)에 전혀 부담이 없다.
  - 공간복잡도: **O(D)** — 입력 배열 제외
    - `check` 안에서 만드는 자릿수 리스트 6개가 각각 최대 D개의 원소를 가진다. 조합을 저장하지 않고 즉시 판정하므로 그 이상 늘어나지 않는다.

### 회고
- 몇 번만에 성공했는지: 2번
- 잘한 점:
  - 자릿수가 다른 수끼리 비교할 때 위치가 어긋나는 문제를 미리 예상하고, 뒤집기 + 0 채우기로 자리를 맞췄다.
  - "각 자리의 합이 10 이상인 곳이 하나도 없어야 한다"는 조건을 그대로 코드로 옮겨, 한 자리라도 넘치면 즉시 `return 0`으로 빠져나왔다.
  - `ans = -1`로 초기화해서 "가능한 조합이 없으면 -1"이라는 예외 케이스를 별도 분기 없이 처리했다.
- 개선할 점:
  (AI)
  - 현재 3중 루프는 순서가 다른 같은 조합 `(i, j, k)`, `(j, i, k)` 등 6가지를 전부 검사한다. `for j in range(i + 1, n)`, `for k in range(j + 1, n)`처럼 오름차순 인덱스만 돌거나 `itertools.combinations(arr, 3)`을 쓰면 검사 횟수가 N³에서 C(N, 3) = 1,140으로 약 6배 줄고, 세 개의 `continue` 조건도 사라진다.
  - 자릿수 리스트를 만들고 길이를 맞추는 과정은 `% 10`과 `// 10`으로 대체할 수 있다. `while a or b or c:` 안에서 `a % 10 + b % 10 + c % 10 >= 10`이면 실패, 아니면 세 수를 모두 `// 10`으로 줄여나가면 된다. 짧은 수는 0이 되어 자연스럽게 0으로 채운 효과가 나므로 `mx`나 패딩 배열이 필요 없다.
  - `check`의 반환값은 `0`/`1` 대신 `False`/`True`가 의도를 더 잘 드러낸다. `list(map(int, list(str(num))))`도 `[int(d) for d in str(num)]`으로 줄일 수 있다.
