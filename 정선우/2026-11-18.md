# 프로그래머스 Lv.2 — 숫자의 표현

### 문제 설명
- 풀이 URL : [숫자의 표현](https://github.com/sunoo2468/codingTestPre/blob/main/Python/%ED%94%84%EB%A1%9C%EA%B7%B8%EB%9E%98%EB%A8%B8%EC%8A%A4/2/12924.%E2%80%85%EC%88%AB%EC%9E%90%EC%9D%98%E2%80%85%ED%91%9C%ED%98%84/%EC%88%AB%EC%9E%90%EC%9D%98%E2%80%85%ED%91%9C%ED%98%84.py)
- 난이도 : Lv.2
- 알고리즘 : 포인터

### 접근 방식 : 투 포인터
1. `left`, `right`를 1로 초기화하고 `total`에 현재 구간의 합을 저장한다.
2. `total < n`이면 `right`를 증가시켜 구간을 확장한다.
3. `total > n`이면 `left`를 증가시켜 구간을 축소한다.
4. `total == n`이면 정답을 증가시키고 `left`를 이동한다.
5. 구간의 합을 매번 다시 계산하지 않고, 숫자를 더하거나 빼면서 갱신한다.

- 시간복잡도 : `O(N)`
- 공간복잡도 : `O(1)`

### 회고

- **몇 번 만에 성공했는지** : 2회
- **잘한 점** : 풀이를 보고 투 포인터의 이동 조건과 구간 합을 갱신하는 방식을 이해할 수 있었다.
- **개선할 점** : 문제를 처음 접했을 때, 연속된 구간이라는 조건에서 투 포인터를 떠올리는 연습이 필요하다.
- **새로 배운 점** : 두 포인터를 이동시키면서 기존 구간의 합을 재사용하면 불필요한 반복 계산을 줄일 수 있다.
- **느낀 점** : 문제 자체는 단순하고 풀이도 어렵지 않았지만, 처음 접근 방법을 생각할 때 순간 당황했다. 막상 풀이를 보니 간단한 구조였고, 알고리즘을 이해하는 것과 직접 떠올리는 것은 다르다는 점을 느꼈다. 그래도 새로운 알고리즘을 처음 접한 것치고는 괜찮았던 문제였다.
