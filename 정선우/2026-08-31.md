### 접근 방식 : 딕셔너리 + 문자열 파싱
- 왜 이 방식으로 풀었나?
  - 차량마다 입차 시간과 누적 주차 시간을 저장해야 하기 때문에 딕셔너리를 사용했다.
  - Lv.1 문제와 달리 한 번에 해결하기보다 문제를 작은 단위로 나누어 접근했다.
    1. 입·출차 기록 분리
    2. 시간을 분 단위로 변환
    3. 차량별 입차 시간 저장
    4. 출차 시 주차 시간 누적
    5. 출차 기록이 없으면 23:59 기준으로 계산
    6. 누적 시간을 기준으로 요금 계산
    7. 차량 번호순으로 정렬

- 구현하며 막혔던 부분
  - 최근 Java를 자주 사용해서 Python과 문법이 혼용되었다.
  - Java의 `HashMap.put()`과 헷갈렸지만 Python 딕셔너리는 `dict[key] = value` 형태로 저장한다.
  - 시간은 시/분을 각각 계산하는 것보다 모두 분으로 변환한 뒤 빼는 것이 훨씬 간단했다.

```python
hour, minute = map(int, time.split(":"))
minutes = hour * 60 + minute
```

  - 차량별 주차 시간을 누적하는 부분은 혼자 해결하지 못했다.

```python
total[car] = total.get(car, 0) + (end_time - start_time)
```

  - 처음에는 `total[car] += ...` 형태로 생각했지만, 해당 차량이 딕셔너리에 처음 등장했다면 `total[car]` 자체가 존재하지 않는다.
  - `get(car, 0)`을 사용하면 값이 존재할 경우 기존 값을 가져오고, 없다면 `0`부터 시작할 수 있다는 것을 알게 되었다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - records 순회 : `O(N)`
  - 차량 번호 정렬 : `O(N log N)`
  - 전체 시간복잡도 : `O(N log N)`
  - 차량별 입차 시간과 누적 시간을 딕셔너리에 저장하므로 공간복잡도 : `O(N)`

### 회고
- 몇 번만에 성공했는지 : 도움을 받아 해결
- 잘한 점 :
  - 입차/출차 시간의 차이를 계산할 때 시와 분을 따로 처리하는 방법을 먼저 떠올렸고, 이를 전체 분으로 변환하면 더 간단하게 계산할 수 있다는 것을 이해했다.
  - 문제를 한 번에 구현하려 하지 않고 필요한 데이터를 먼저 정의한 뒤 입·출차 처리, 누적 시간 계산, 미출차 처리, 요금 계산으로 나누어 접근했다.

- 개선할 점 :
  - 실제 코딩테스트 문제인 Lv.2를 풀어보니 지금까지 풀었던 Lv.1보다 문제의 분량과 고려해야 할 조건이 크게 늘었다.
  - Lv.1이 하나의 문제를 해결하는 느낌이었다면, 이번 문제는 여러 개의 작은 문제를 각각 해결한 뒤 합쳐서 하나의 답을 만드는 느낌이었다.
  - 앞으로 문제가 길어질수록 바로 코드를 작성하기보다 먼저 필요한 데이터와 처리 순서를 정의하고 문제를 작은 단위로 나누어야겠다.
  - 최근 Java 사용이 잦아지면서 Python과 문법이 섞였다. 이전에는 쉽게 사용했던 딕셔너리, `split()`, 언패킹 등의 문법에서도 막혔기 때문에 코딩테스트 전 Python 문법을 다시 익숙하게 만들 필요가 있다.
  - `dict.get(key, 0)`을 이용한 누적 방식은 혼자 떠올리지 못했다. 딕셔너리에서 값이 존재하지 않을 수 있는 경우 기본값을 주고 누적하는 패턴을 기억해두어야겠다.
