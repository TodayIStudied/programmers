### 접근 방식 : 1. backtrack 완전탐색
- k 최대 5, n 최대 20 이라 H(5, 20) 으로 값이 작아 완전탐색해도 시간복잡도가 크게 늘지 않을 것으로 판단했다
- 이에 backtrack을 통해 상담인원을 배치하고 전원 배치 되었을 때의 시간을 계산하여 최솟값을 구하였다
- O( H(5, 20) * k * R logR) = 약 500만 에 해결 가능하다

### 접근 방식 : 2. DP + Greedy
- 문제 해결 이후 다른 방안의 답을 찾다가 위 방법을 확인할 수 있었다
- 각 유형의 상담원이 n명일때의 시간은 모두 동일하므로 한 번 기록한 이후에는 해당 값을 재활용할 수 있다 -> DP
- 또한 인원을 추가할 수록 대기시간 감소량이 줄어드는 한계 효용 감소의 양상을 띄기 떄문에 그리디로 최적해를 구할 수 있다
- 이를 통해 시간 복잡도를 더욱 낮출 수 있다 => $\mathcal{O}\left(K \cdot N \cdot R \log R + (N-K) \cdot K\right)$

### 회고 
- 몇 번만에 성공했는지 : 1번
- 잘한 점 : backtracking 사용 판단을 빨리한 점, 로깅을 붙여 에러를 빠르게 해결한 점
- 개선할 점 : dp 및 greedy 알고리즘을 적용하여 더욱 개선할 여지가 있다
