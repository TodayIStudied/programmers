### 접근 방식 : BFS + Queue
- 왜 이 방식으로 풀었나?
  - 처음에는 BFS와 DP의 차이가 헷갈렸지만, BFS는 값을 비교해 최적값을 선택하는 것이 아니라 **가까운 위치부터 순서대로 탐색하기 때문에 최단거리를 구할 수 있다**는 것을 알게 되었다.
  - 시작점 `(0, 0)`부터 상하좌우로 이동 가능한 좌표를 Queue에 넣어가며 탐색했다.
  - 방문한 좌표는 딕셔너리에 저장하고, 이전 위치까지의 거리에 `+1`하여 현재 위치까지의 거리를 기록했다.

```python
visited[(nx, ny)] = visited[(x, y)] + 1
```

- BFS의 흐름
  1. 시작 좌표를 Queue에 저장
  2. Queue의 가장 앞 좌표를 `popleft()`
  3. 현재 좌표의 상하좌우 확인
  4. 맵 내부이면서 이동 가능하고 방문하지 않은 좌표라면 거리 저장 후 Queue에 추가
  5. Queue가 빌 때까지 반복
  6. 목적지의 `visited` 값을 반환하고, 방문하지 못했다면 `-1` 반환

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 각 칸을 최대 한 번 방문하므로 시간복잡도 : `O(N × M)`
  - 방문 좌표와 거리를 저장하므로 공간복잡도 : `O(N × M)`
  - 별도의 `visited`를 사용하지 않고 `maps` 자체에 거리를 기록하는 방법으로 공간을 줄일 수도 있다.

### 회고
- 몇 번만에 성공했는지 : 도움을 받아 해결
- 잘한 점 :
  - DFS, BFS, DP의 차이를 비교하면서 각각 어떤 상황에서 사용하는지 이해했다.
  - `visited`를 좌표를 key로 두고 최단거리를 value로 저장하는 방식을 이해했다. (익숙치 않으니깐, 메모리 효율을 생각하기보단 정석대로)
  - 최종적으로 직접 작성한 BFS 코드의 구조와 각 코드가 필요한 이유를 이해하고 해결했다.

- 개선할 점 :
  - 지금까지 풀었던 문제 중 가장 어렵게 느껴졌다. BFS뿐만 아니라 Queue, 좌표 이동, 범위 검사, 방문 처리, 거리 계산을 한 번에 사용해야 해서 구현 과정이 익숙하지 않았다.
  - 처음에는 방문할 때마다 `answer += 1`을 하면 거리라고 생각했지만, 이는 방문한 칸의 개수일 뿐 최단거리가 아니다.
  - 새로운 좌표의 거리는 `visited[(nx, ny)] += 1`이 아니라 **이전 좌표의 거리에서 1을 누적**해야 한다는 것을 배웠다.

```python
visited[(nx, ny)] = visited[(x, y)] + 1
```

  - BFS는 코딩테스트에서 자주 사용되는 유형인 만큼 비슷한 문제를 추가로 풀면서 `Queue → 상하좌우 탐색 → 방문 확인 → 거리 기록` 구조에 익숙해져야겠다.
