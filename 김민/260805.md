### 접근 방식 : 1. DFS + UnionFind
- 파이프의 타입별 그룹화를 위한 유니온파인드
  - 코드 복잡도 및 탐색 진행 시 복잡도 상승
  - 추가 전파 시 확인 어려움
  
- 모든 케이스 탐색을 위한 DFS 사용
  - max K가 10이기 떄문에 DFS를 사용
  - Pruning 없이도 시간 복잡도가 O(3 * 2^9 = 1536) 이므로 괜찮다고 판단함

### 접근 방식 : 2. DFS + BFS
- 1번 방식에서 unionFind를 BFS로 변경
  - 저장 방식을 edge 기준으로 수정
  - infected 대상으로만 BFS 하도록 수정

### 회고 
- 몇 번만에 성공했는지 : 1번
- 잘한 점 : 접근법은 2번 만에 성공함
- 개선할 점 : pruning 등 적용하면 성능 개선 여지 있음, 오랜만에 해서 문법 좀 까먹음.
