## 비둘기와 전기줄

### 문제 설명

- 문제명: 비둘기와 전기줄
- 문제 URL: [비둘기와 전기줄](https://www.codetree.ai/trails/complete/curated-cards/intro-pigeons-and-electric-cords)
- 풀이 URL: [내 풀이 코드](https://github.com/HappyPotatohappy/CodingTest/blob/53db867661711350053dbac135225e64565c4fcf/trail2/비둘기와%20전기줄/pigeons-and-electric-cords.py)
- 사용 언어: Python
- 분류: Trail 2 / 케이스별로 나누기 / 일어난 상황에 대한 추론 (난이도: 쉬움)
- 1~10번 비둘기가 전기줄의 왼쪽(0) 또는 오른쪽(1)에 앉아 있는 모습을 시간 순서대로 N번 관찰한 기록이 주어진다.
- 각 기록은 `(비둘기 번호, 위치)`이며, 비둘기가 전기줄을 건너간 횟수의 **최솟값**을 출력한다.

### 접근 방식 : 1. 비둘기 번호로 안정 정렬 후 인접한 기록 비교

- 왜 이 방식으로 풀었나?
  - 같은 비둘기의 연속된 두 관찰에서 위치가 다르면, 그 사이에 최소 1번은 건넜다.
  - 위치가 같으면 건너지 않았다고 보는 것이 최소이므로 0번으로 센다.
  - 따라서 답은 **"같은 비둘기의 연속된 두 관찰 중 위치가 바뀐 쌍의 개수"**다.
  - 기록을 비둘기 번호로 정렬하면 같은 비둘기의 기록이 한데 모이므로, 인접한 두 기록만 비교하면 된다.

- 정렬이 정답을 보장하는 이유
  - `t.sort(key=lambda x: x[0])`처럼 **비둘기 번호만** 키로 쓰면, 번호가 같은 기록끼리는 입력 순서(관찰 순서)가 그대로 유지된다.
  - 파이썬의 `sort`가 **안정 정렬**(stable sort)이기 때문이다. 이 풀이의 정답성은 이 성질에 기대고 있다.

- 인접한 기록을 비교하는 방법
  - `i`를 0부터 N - 2까지 순회하며 `t[i]`와 `t[i + 1]`을 비교한다.
  - `pi == p_nxt and xi != x_nxt`, 즉 같은 비둘기인데 위치가 바뀌었으면 `cnt += 1`.
  - 번호가 다른 비둘기의 경계(`pi != p_nxt`)는 세지 않는다.

- 구현에서 주의할 점
  - `t.sort()`나 `sorted(t)`처럼 `(번호, 위치)` 전체를 키로 쓰면, 같은 비둘기의 기록이 위치 순으로 재배열되어 관찰 순서가 깨진다.
  - 위 예시에서 3번이 0 → 0 → 1 → 1로 바뀌어 2가 출력된다. 랜덤 입력 300개로 확인했을 때 256개가 오답이었다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(N log N)**
    - 정렬에 O(N log N), 인접 비교에 O(N)이 든다.
  - 공간복잡도: **O(N)**
    - 모든 기록을 리스트에 저장한 뒤 정렬한다.

### 접근 방식 : 2. 비둘기별 마지막 위치를 기억하며 한 번 순회

- 왜 이 방식으로 생각했나? (9월 1일에 처음 풀었을 때의 방식)
  - 정렬하지 않고 입력 순서대로 읽으면서, 비둘기마다 **마지막으로 본 위치**만 기억해도 같은 판정을 할 수 있다.
  - `before = [-1] * 11`로 1~10번 비둘기의 마지막 위치를 저장한다. `-1`은 아직 관찰되지 않았다는 뜻이다.
  - 처음 관찰된 비둘기는 위치만 기록한다.
  - 이미 관찰된 비둘기의 위치가 `before[p]`와 다르면 `cnt += 1`하고 `before[p]`를 갱신한다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(N)**
    - 기록을 한 번 순회하며, 매번 배열 조회와 갱신만 한다.
  - 공간복잡도: **O(K)** (K = 비둘기 수, 여기서는 10)
    - 9월 1일 풀이는 입력을 리스트에 저장해 O(N)이지만, 입력을 받으면서 바로 처리하면 `before` 배열만 필요하다.
  - 비교
    - 접근 1은 정렬 때문에 O(N log N)이고, 정렬 안정성이라는 조건을 알고 있어야 정답이 보장된다.
    - 접근 2는 정렬 없이 O(N)에 끝나고, 관찰 순서를 그대로 쓰므로 안정성을 신경 쓸 필요가 없다.
    - 비둘기 번호 범위가 작아 배열로 상태를 둘 수 있다는 점이 접근 2의 전제다. 번호 범위가 크면 딕셔너리를 쓰면 된다.
    - 이 문제의 입력 크기에서는 두 방식 모두 충분히 빠르다.

### 회고

- 몇 번만에 성공했는지: 1번 - 다른 방법으로 2번
- 잘한 점:
  - "최소 횟수"를 같은 비둘기의 연속된 관찰 쌍 단위로 쪼개 생각해, 각 쌍에서 위치가 바뀐 경우만 세면 된다는 점을 정확히 잡았다.
  - 정렬 키를 비둘기 번호 하나로만 잡아 관찰 순서를 유지했다.
  - `pi == p_nxt` 조건으로 서로 다른 비둘기 사이의 경계를 세지 않도록 처리했다.
- 개선할 점 (AI):
  - 정답이 정렬 안정성에 기대고 있으므로 `# 안정 정렬: 같은 번호 안에서는 관찰 순서 유지` 같은 주석을 남겨 두면, 나중에 키를 바꾸다 틀리는 일을 막을 수 있다.
  - 인덱스로 `t[i]`, `t[i + 1]`을 꺼내는 대신 `for (p1, x1), (p2, x2) in zip(t, t[1:])`로 인접한 쌍을 바로 비교하면 더 간결하다.
