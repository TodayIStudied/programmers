## 독서실의 거리두기 3

### 문제 설명

- 문제명: 독서실의 거리두기 3
- 문제 URL: [독서실의 거리두기 3](https://www.codetree.ai/trails/complete/curated-cards/intro-study-cafe-keeping-distance-3)
- 풀이 URL: [내 풀이 코드](https://github.com/HappyPotatohappy/CodingTest/blob/ff8c3ef36dba7437347e51977debb671e469375f/trail2/독서실의%20거리두기%203/study-cafe-keeping-distance-3.py)
- 사용 언어: Python
- 분류: Trail 2 / 케이스별로 나누기 / 좋은 전략을 추려내기 (난이도: 보통)
- N개의 좌석이 일렬로 있고, 사람이 앉은 자리는 `1`, 빈자리는 `0`인 문자열로 주어진다. 양 끝 자리에는 항상 사람이 앉아 있다.
- 빈자리 하나에 한 명을 더 앉힐 때, **가장 가까운 두 사람 사이의 거리**가 최대가 되도록 하고 그 거리를 출력한다.
- 두 사람 사이의 거리는 좌석 번호의 차이다.

### 접근 방식 : 1. 가장 긴 간격의 가운데에 앉히기 (전략 추려내기)

- 왜 이 방식으로 풀었나?
  - 새 사람은 반드시 인접한 두 사람 사이의 간격 중 하나에 들어간다. 길이 `g`인 간격의 가운데에 앉히면 그 간격은 `g // 2`와 `g - g // 2`로 나뉘고, 나머지 간격은 그대로다.
  - 따라서 결과는 **`min(나머지 간격들의 최솟값, g // 2)`**이다.
  - 가장 긴 간격을 고르면 `g // 2`가 가장 커진다.
  - 다른 간격을 고르면 `g // 2`가 같거나 작아진다. 가장 짧은 간격을 고르면 나머지 간격의 최솟값은 커질 수 있지만, 그 짧은 간격이 반으로 쪼개지므로 결과가 더 나아지지 않는다.
  - 그래서 빈자리를 전부 시도해 볼 필요 없이 **"가장 긴 간격의 가운데"** 하나만 확인하면 된다.

- 간격을 구하는 방법 (`check_long`)
  - 사람이 앉은 자리 `i`마다 오른쪽으로 다음 사람 `j`를 찾고 바로 `break`한다.
  - `[j - i, i, j]`를 모아 거리 기준 내림차순으로 정렬한다.
  - 정렬 결과의 첫 원소가 가장 긴 간격, 마지막 원소가 가장 짧은 간격이다.

- 전체 흐름
  - 처음 `check_long`으로 가장 긴 간격 `[i, j]`를 찾는다.
  - `(i + j) // 2` 자리에 사람을 앉힌다.
  - 다시 `check_long`을 돌려 가장 짧은 간격 `tmp3[-1][0]`을 출력한다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(N + K log K)** (K = 앉아 있는 사람 수, 최악 O(N log N))
    - `check_long`의 이중 반복문은 각 간격을 한 번씩만 훑고 `break`하므로 합쳐서 O(N)이다.
    - 간격 목록 정렬에 O(K log K)가 든다. 이 과정을 두 번 반복한다.
  - 공간복잡도: **O(N)**
    - 좌석 리스트 O(N)과 간격 목록 O(K)를 저장한다.

### 접근 방식 : 2. 모든 빈자리에 앉혀 보는 완전탐색

- 왜 이 방식으로 생각했나?
  - 접근 1의 전략이 맞는지 확인하는 기준이 되는 가장 단순한 방법이다.
  - 빈자리 하나마다 사람을 앉혀 보고 가장 가까운 두 사람 사이의 거리를 구한 뒤, 그중 최댓값을 고른다.
  - 커리큘럼 이름처럼 이 완전탐색에서 출발해 **"좋은 전략만 추려내면"** 접근 1이 된다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(N²)**
    - 빈자리 O(N)개마다 거리 최솟값을 O(N)에 다시 계산한다.
  - 공간복잡도: **O(N)**
    - 좌석 리스트 하나를 복사해 가며 쓴다.
  - 비교
    - 접근 1은 시도할 위치를 하나로 줄여서 정렬 비용을 빼면 선형 시간에 끝난다.
    - 완전탐색은 정답 근거가 단순한 대신 N이 커질수록 느려진다.

### 회고

- 몇 번만에 성공했는지: 1번
- 잘한 점:
  - 빈자리를 전부 시도하지 않고, "가장 긴 간격의 가운데"라는 전략 하나로 줄여서 풀었다.
  - 다음 사람을 찾으면 바로 `break`해서 간격 계산을 O(N)으로 유지했다.
  - 간격 정보를 `[거리, 시작, 끝]`으로 묶어서 가장 긴 간격의 위치와 가장 짧은 거리를 같은 함수로 구했다.
    
- 개선할 점 (AI):
  - `check_long(seat)`의 매개변수 `seat`를 쓰지 않고 전역 `seats`를 참조하고 있다. 매개변수를 쓰도록 바꾸면 함수가 입력에만 의존해서 테스트하기 쉬워진다.
  - `get_dist`는 정의만 하고 쓰지 않으므로 지우는 게 좋다.
  - 필요한 건 가장 긴 간격과 가장 짧은 간격뿐이라 정렬 대신 `max()` / `min()`을 쓰면 O(N)이 된다.
  - 두 번째 `check_long` 없이 `min(나머지 간격들의 최솟값, 최대 간격 // 2)`로 바로 답을 구할 수도 있다.
