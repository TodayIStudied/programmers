### 접근 방식 : 1. 문자열 빈도수 카운팅 + 그리디
- 왜 이 방식으로 풀었나?
  - 팰린드롬을 만들려면 등장 횟수가 홀수인 문자가 최대 1개여야 하므로 딕셔너리로 빈도수부터 집계
  - 홀수 개수가 2개 이상이면 팰린드롬이 불가능하므로 "I'm Sorry Hansoo" 출력
  - 사전순으로 앞서야 하므로 알파벳 순으로 개수의 절반씩 half 문자열에 추가
  - 홀수 개수 문자는 가운데(mid)에 배치하고 `half + mid + half[::-1]` 형태로 대칭 조립
- 시간복잡도, 공간복잡도 관점에서의 성능 비교 
  - 시간복잡도: O(N log N) (문자열 길이 N <= 50으로 매우 작아 즉시 완료)
  - 공간복잡도: O(N) (알파벳 카운트 딕셔너리와 결과 문자열)
  - 메모리: 약 31MB, 시간: 40ms 내외

### 회고 
- 몇 번만에 성공했는지 : 2번
- 잘한 점 : 홀수 개수 체크로 예외 처리 먼저 거르고 절반 문자열 뒤집기로 깔끔하게 푼 점
- 개선할 점 :
  - 처음에 문자열 뒤집을 때 `reversed()` 객체를 str에 바로 더하려다 TypeError 발생함, 슬라이싱 `[::-1]` 사용하기
  - 딕셔너리 순회할 때 `sorted(c.keys())`로 처음부터 정렬해서 돌리면 중간 배열 없이 코드가 더 간결해짐
