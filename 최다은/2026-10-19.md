### 접근 방식 : 1. 백트래킹 
- 왜 이 방식으로 풀었나?
  - 하나의 item에 대해 a가 가져가거나 b가 가져가거나 둘 중 하나임
  - 이진트리가 뻗어나가는 경우가 존재한다고 봐야
  - 그런데 item 개수가 최대 40이라서 2^40 탐색 무조건 터짐 -> 처음에 고려 안해서 터졌음
  - (a 누적값, b 누적값, 현재 idx)까지 도달하는 최소값 만드는 경로 여러개일 수 있는데 중복 탐색될 필요 없음
  - 그렇기에 visited set을 따로 두어서 이미 방문했으면 방문 x -> a,b,items 다 숫자 작아서 O(N) 탐색 자체는 ok
  - ... 근데 정해가 백트래킹은 아닌 듯
  ```python
  def solution(info, n, m):
      answer = int(1e6)
      items_cnt = len(info)
      visited = set()
      
      def bt(a,b,idx):
          nonlocal answer
          
          if idx==items_cnt:
              answer = min(answer,a)
              return 
          
          if (a,b,idx) in visited:
              return 
          
          visited.add((a,b,idx))
          
          if a+info[idx][0]<n:
              bt(a+info[idx][0],b,idx+1)
          if b+info[idx][1]<m:
              bt(a,b+info[idx][1],idx+1)
              
      bt(0,0,0)
      return answer if answer!=int(1e6) else -1
  """
  백트래킹인데
  n개 또는 m개 이상이면 탐색 중단
  그리고 모든 물건 탐색하지 않았다면 a 훔친 개수 업데이트 안함. 
  """
  ```
- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 메모리: 15.1 MB, 시간: 11.16 ms

### 접근 방식 : 2. DP
- 왜 이 방식으로 풀었나?
  - 정해는 DP인 듯
  - dp[b] : B가 훔친 누적값이 b일 때 A의 최소 누적값
  - item을 하나씩 늘려가며 item 조합별로 A 최소 누적값 달라지는 것 업데이트
  ```python
  def solution(info, n, m):
      INF = float('inf')
  
      dp = [INF] * m
      dp[0] = 0
      
      for a, b in info:
          next_dp = [INF] * m
  
          for j in range(m):
              if dp[j] == INF:
                  continue
  
              # A가 훔치는 경우
              if dp[j] + a < n:
                  next_dp[j] = min(next_dp[j], dp[j] + a)
  
              # B가 훔치는 경우
              if j + b < m:
                  next_dp[j + b] = min(next_dp[j + b],dp[j])
  
          dp = next_dp
  
      answer = min(dp)
      return answer if answer != INF else -1
  ```
- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 메모리: 11.6 MB, 시간: 0.27 ms
  - 백트래킹에 비해 훨씬 시간 적게 소요됨.
