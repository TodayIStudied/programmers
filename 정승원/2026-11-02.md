## 피보나치 수

### 문제 설명

- 문제명: 피보나치 수
- 문제 URL: [피보나치 수](https://www.codetree.ai/trails/complete/curated-cards/intro-fibonacci-number)
- 풀이 URL: [내 풀이 코드](https://github.com/HappyPotatohappy/CodingTest/blob/6675c417ffbd25d5539f84717f939450b8b52501/trail4/피보나치%20수/fibonacci-number.py)
- 사용 언어: Python
- 분류: Trail 4 / DP I / subproblem을 그대로 합치면 되는 DP (난이도: 쉬움)
- 피보나치 수열은 1번째와 2번째 항이 1이고, 3번째 항부터는 바로 앞 두 항의 합이다. (`1, 1, 2, 3, 5, 8, ...`)
- 정수 n이 주어질 때 n번째 피보나치 수를 출력한다.

### 접근 방식 : 1. 메모이제이션을 이용한 재귀 (Top-down DP)

- 왜 이 방식으로 풀었나?
  - 점화식 `F(n) = F(n - 1) + F(n - 2)`를 그대로 재귀로 옮기면 같은 값을 계속 다시 계산한다. `F(n - 1)`을 구하는 과정에서 이미 `F(n - 2)`를 구했는데, `F(n - 2)`를 처음부터 또 계산하기 때문이다.
  - 실제로 메모 없이 `F(30)`을 구하면 함수가 **1,664,079번** 호출된다.
  - 한 번 구한 값을 `dp` 배열에 저장해 두고 다시 필요할 때 꺼내 쓰면 각 항을 한 번씩만 계산한다. 같은 `F(30)`에서 호출 횟수가 **57번**으로 줄어든다.
  - 커리큘럼 이름처럼 큰 문제의 답이 작은 문제 두 개의 답을 **그대로 더한 값**이라서, 작은 문제의 답을 저장해 두는 것만으로 풀린다.

- 구현 방법
  - `dp = [-1] * (n + 1)`로 만들고, -1은 "아직 계산하지 않음"을 뜻한다.
  - `n == 1` 또는 `n == 2`이면 `dp[n] = 1`로 채운다.
  - `dp[n] != -1`이면 저장된 값을 바로 반환한다.
  - 아니면 `dp[n] = fib(n - 1) + fib(n - 2)`를 계산해 저장하고 반환한다.


- 구현에서 주의할 점
  - 재귀 깊이가 n에 비례한다. 파이썬의 기본 재귀 한도를 넘으면 `RecursionError`가 난다. 로컬에서 확인해 보니 n = 1,000까지는 동작했고 n = 1,100에서 에러가 났다.
  - 이 문제의 입력 범위에서는 문제없이 통과했지만, n이 큰 문제라면 `sys.setrecursionlimit`으로 한도를 늘리거나 접근 2를 써야 한다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(n)**
    - 각 항을 한 번씩만 계산하고, 그 외 호출은 저장된 값을 바로 반환한다. 전체 호출 수는 약 2n번이다.
  - 공간복잡도: **O(n)**
    - `dp` 배열 O(n)과 재귀 호출 스택 O(n)을 쓴다.

### 접근 방식 : 2. 작은 항부터 차례로 채우는 반복문 (Bottom-up DP)

- 왜 이 방식으로 생각했나?
  - 제출 코드에 주석으로 남겨 둔 방식이다.
  - `F(n)`을 구하려면 `F(n - 1)`과 `F(n - 2)`만 있으면 되므로, 1번째 항부터 순서대로 배열을 채우면 재귀 없이도 같은 값을 구할 수 있다.
  - `tabu[1] = tabu[2] = 1`로 두고, `i = 3`부터 `n`까지 `tabu[i] = tabu[i - 1] + tabu[i - 2]`를 계산한다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(n)**
    - 반복문 한 번으로 2번째 항부터 n번째 항까지 채운다.
  - 공간복잡도: **O(n)**
    - 배열 하나만 쓰고 재귀 스택이 없다. 앞 두 항만 변수 두 개로 들고 가면 **O(1)**까지 줄일 수 있다.
  - 비교
    - 두 방식의 시간복잡도는 같다.
    - 접근 1은 점화식을 그대로 옮겨서 읽기 쉽고, 필요한 항만 계산한다. 대신 재귀 깊이 제한이 있고 함수 호출 비용이 든다.
    - 접근 2는 재귀 제한이 없고 함수 호출 비용도 없다. 계산 순서를 직접 정해야 하는데, 피보나치처럼 순서가 명확하면 오히려 더 단순하다.
    - n이 매우 크면 행렬 거듭제곱으로 **O(log n)**에 구할 수도 있지만, 이 문제의 범위에서는 필요 없다.
    - n = 1부터 90까지 실제 피보나치 수와 비교했을 때 제출 코드는 모두 맞았다.

### 회고

- 몇 번만에 성공했는지: 1번
- 잘한 점:
  - 재귀 점화식에 메모이제이션을 붙여서 같은 항을 다시 계산하지 않게 했다.
  - -1을 "아직 계산하지 않음"으로 정해서, 저장된 값이 있는지 한 번에 확인했다.
  - Top-down 방식으로 제출하면서 Bottom-up 방식도 직접 작성해 봤다.
- 개선할 점 (AI):
  - 기저 조건에서 `dp`를 채운 뒤 아래의 `dp[n] != -1` 확인을 거쳐 반환하는 흐름이라 한 번 더 따라가야 이해된다. 함수 맨 앞에 `if n <= 2: return 1`을 두면 기저 조건이 바로 드러난다.
  - 함수 매개변수 `n`이 전역 변수 `n`과 이름이 같다. 동작에는 문제가 없지만 `fib(k)`처럼 다른 이름을 쓰면 어느 `n`인지 헷갈리지 않는다.
  - 주석으로 남긴 Bottom-up 코드는 n = 1일 때 에러가 나고 반복 시작점이 2로 되어 있다. 계속 둘 거라면 `range(3, n + 1)`로 고치고 n = 1을 따로 처리하거나, 앞 두 항만 변수로 들고 가는 방식으로 바꾸면 좋다.
