## 최소 와이파이 수

### 문제 설명

- 문제명: 최소 와이파이 수
- 문제 URL: [최소 와이파이 수](https://www.codetree.ai/trails/complete/curated-cards/intro-minimum-number-of-wifi)
- 풀이 URL: [내 풀이 코드](https://github.com/HappyPotatohappy/CodingTest/blob/3f4fbafc1e56431bc2385b6ab82305587937d332/trail2/최소%20와이파이%20수/minimum-number-of-wifi.py)
- 사용 언어: Python
- 분류: Trail 2 / Ad-Hoc / 지극히 최선인 전략이 확실히 정해지는 경우 (난이도: 보통)
- 1번부터 n번까지 일렬로 놓인 칸마다 사람이 있으면 `1`, 없으면 `0`이 주어진다.
- x번 칸에 와이파이를 설치하면 `x - m`번부터 `x + m`번까지의 사람이 와이파이를 쓸 수 있다.
- 모든 사람이 와이파이를 쓸 수 있도록 할 때 필요한 와이파이의 최소 개수를 출력한다.

### 접근 방식 : 1. 덮이지 않은 가장 왼쪽 사람 기준으로 최대한 오른쪽에 설치 (그리디)

- 왜 이 방식으로 풀었나?
  - 아직 덮이지 않은 사람 중 가장 왼쪽 사람(위치 `i`)은 어떤 와이파이로든 반드시 덮어야 하고, 그 와이파이의 위치는 `i + m` 이하여야 한다.
  - 그 범위에서 가장 오른쪽인 `i + m`에 설치하면 `i`를 덮으면서 오른쪽으로 `i + 2m`까지 가장 멀리 덮을 수 있다.
  - `i` 왼쪽의 사람은 이미 다 덮였으므로 왼쪽으로 덮는 범위는 손해가 아니다. 다른 위치에 두면 오른쪽으로 덮는 범위만 줄어든다.
  - 그래서 매번 **"덮이지 않은 가장 왼쪽 사람 + m"**에 설치하는 것이 확실히 최선이다.

- 설치 위치를 정하는 방법 (`check_wifi`)
  - `idx`부터 오른쪽으로 훑으며 처음 나오는 사람 `i`를 찾는다.
  - `i + m <= n`이면 `i + m`에 설치하고, 다음 탐색은 덮인 범위 바로 다음 칸인 `i + 2m + 1`부터 시작한다.
  - `i + m > n`이면 마지막 칸 `n`에 설치한다. 이 경우 `n - m < i`이므로 남은 사람이 모두 덮여서 탐색을 끝낸다.
  - 설치한 위치를 `wifi` 배열에 1로 표시하고, 마지막에 그 합을 출력한다.

- 특수한 경우 처리
  - `m == 0`이거나 `n == 1`이면 사람 수가 답이다.
  - `2m > n`이면 와이파이 하나로 전체를 덮을 수 있으므로 사람이 있으면 1, 없으면 0이다.


- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(n)**
    - 각 탐색은 이전에 덮인 범위 다음부터 시작하므로 모든 칸을 최대 한 번씩 훑는다. 마지막 합 계산도 O(n)이다.
  - 공간복잡도: **O(n)**
    - 입력 배열과 `wifi` 배열을 저장한다.

### 접근 방식 : 2. 설치 위치의 모든 조합을 시도하는 완전탐색

- 왜 이 방식으로 생각했나?
  - 접근 1의 전략이 정말 최선인지 확인하는 기준이 되는 가장 단순한 방법이다.
  - 와이파이를 설치할 칸의 모든 부분집합을 만들어 보고, 모든 사람을 덮는 부분집합 중 크기가 가장 작은 것을 고른다.
  - 커리큘럼 이름처럼 이 문제는 최선의 전략이 확실히 하나로 정해지기 때문에 이 모든 조합을 볼 필요가 없다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(2ⁿ · n²)**
    - 부분집합 2ⁿ개마다 사람 n명이 각각 설치된 와이파이 최대 n개 중 하나에 덮이는지 확인한다.
  - 공간복잡도: **O(n)**
    - 현재 부분집합의 설치 위치만 저장한다.
  - 비교
    - 완전탐색은 n이 20만 넘어도 쓰기 어렵지만, 그리디는 n에 비례하는 시간에 끝난다.
    - n ≤ 13인 랜덤 입력 300개에서 완전탐색과 비교했고, n ≤ 100인 랜덤 입력 300개에서는 그리디 기준 코드와 비교했다.

### 회고

- 몇 번만에 성공했는지: 1번
- 잘한 점:
  - "덮이지 않은 가장 왼쪽 사람 + m"에 설치하는 것이 확실히 최선이라는 점을 잡아서 그리디로 풀었다.
  - 다음 탐색을 덮인 범위 바로 다음 칸(`i + 2m + 1`)부터 시작해 이미 덮인 칸을 다시 보지 않았다.
  - 설치 위치가 범위를 넘을 때 마지막 칸에 설치하는 경우를 따로 처리했다.
  - 함수에 주석으로 의도를 남겨서 코드만 봐도 전략이 드러난다.
- 개선할 점 (AI):
  - `m == 0`, `n == 1`, `2m > n` 특수 처리는 없어도 일반 로직이 같은 답을 낸다. 특수 처리를 지운 코드로도 같은 랜덤 테스트를 모두 통과했다. 분기가 줄면 실수할 곳도 줄어든다.
  - `check_wifi`가 `0`과 `None` 두 가지로 종료를 알리고 있다.
