### 접근 방식 : Dictionary + 정렬
- 왜 이 방식으로 풀었나?
  -  귤의 종류별 개수를 구한 뒤, 개수가 많은 종류부터 선택하면 필요한 귤의 종류를 최소화할 수 있다고 생각했다.
  -  Dictionary를 이용해 `귤 크기 : 개수` 형태로 저장했다.
  -  `count.values()`를 내림차순으로 정렬하고 큰 값부터 `k`에서 빼면서 선택한 종류의 수를 계산했다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 귤의 개수를 `N`, 귤 종류의 수를 `M`이라고 하면 빈도 계산은 `O(N)`이다.
  <br> 종류별 개수 `M`개를 정렬하므로 `O(M log M)`이 필요하다.
  <br> 따라서 전체 시간복잡도는 `O(N + M log M)`이다.
  - 처음에는 `pop(0)`을 사용했는데 List의 첫 번째 값을 삭제할 때 `O(N)`이 필요해 일부 테스트에서 시간 초과가 발생했다.
  <br> 값을 삭제할 필요 없이 정렬된 리스트를 직접 순회하도록 변경하여 해결했다.

- 잘한 점 :
  - 처음부터 **종류별 개수를 구하고 개수가 많은 종류부터 선택한다**는 핵심 접근은 올바르게 생각했다.
  - Dictionary를 이용해 각 귤 크기의 개수를 직접 계산했다.
  - 정확성은 대부분 통과하지만 일부 테스트에서만 시간 초과가 발생하는 것을 보고 로직 문제가 아니라 성능 문제라는 것을 확인했다.
  - 기존의 `for i in range(len(tangerine))`에서 인덱스가 필요하지 않다는 것을 확인하고 직접 다음과 같이 변경했다.

```python
for size in tangerine:
```

  - 문제를 해결한 뒤 다른 사람의 풀이와 비교해보니 내가 직접 구현한 알고리즘이 `Counter`를 이용한 풀이와 거의 동일하다는 것도 확인했다.

```python
from collections import Counter

count = Counter(tangerine)
```

  - 내가 직접 구현했던 다음 코드:

```python
count = {}

for size in tangerine:
    if size in count:
        count[size] += 1
    else:
        count[size] = 1
```

  를 `Counter`를 사용하면 한 줄로 처리할 수 있다는 것을 새롭게 알게 되었다.
  - 다른 사람의 코드가 더 짧더라도 반드시 더 효율적인 것은 아니며, 어떤 데이터를 정렬하는지도 확인해야 한다는 것을 알게 되었다.

- 개선할 점 :
  - `.sort()`와 `sorted()`의 차이를 다시 확실하게 익혀야겠다.

```python
arr.sort()                         # 원본 자체 정렬, 반환값 None
sorted(arr)                        # 정렬된 새로운 List 반환
sorted(arr, reverse=True)          # 내림차순
```

  - `pop(0)`은 값을 실제로 삭제하지만 List의 앞에서 삭제하기 때문에 `O(N)`이 필요하다는 것을 기억해야겠다.

```python
arr.pop()      # 마지막 값 제거 : O(1)
arr.pop(0)     # 첫 번째 값 제거 : O(N)
```

  -  디버깅을 위해 반복문 안에서 사용한 `print()`는 원인을 확인한 뒤 반드시 제거해야 한다. 실제 제출에서도 출력량이 너무 많아 실행 오류가 발생했다.
