### 접근 방식 : 구현 / 2차원 배열
- 왜 이 방식으로 풀었나?
  - 먼저 `rows × columns` 크기의 2차원 행렬을 생성했다.
  - 회전 영역을 위 → 오른쪽 → 아래 → 왼쪽의 네 방향으로 나누어 직접 값을 한 칸씩 이동시키는 방식으로 구현했다.
  - 값을 덮어쓰기 전에 `temp`에 기존 값을 저장하고, `change`에 다음으로 이동시킬 값을 계속 넘겨주는 방식으로 회전시켰다.
  - 회전시키는 과정에서 `smallest`를 함께 갱신하여 별도의 최소값 탐색을 하지 않았다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 각 Query마다 해당 사각형의 테두리만 순회하므로 전체 행렬을 매번 탐색할 필요가 없다.
  - 별도의 테두리 배열을 만들지 않고 `change`, `temp`만 사용하여 직접 행렬을 수정했다.

### 회고
- 몇 번만에 성공했는지 : 힌트를 받아 직접 구현 후 성공 (1회)

- 잘한 점 :
  - 행렬 생성부터 Query의 좌표 변환, 네 방향의 회전까지 직접 구현하여 최종적으로 테스트를 통과했다.
  - 테두리를 `위 → 오른쪽 → 아래 → 왼쪽`으로 나누어 처리하는 방법을 이해했다.
  - 처음에는 회전되는 값을 별도의 리스트에 담는 방법도 생각했지만, 테두리만 추출하는 구현 방법이 떠오르지 않아 `change`를 이용해 직접 값을 이동시키는 방법으로 방향을 바꾸었다.
  - 회전과 동시에 최소값을 계산하도록 구현했다.

- 개선할 점 :
  - 테두리만 별도의 리스트에 저장한 뒤 회전시키는 방법을 생각했음에도, **2차원 행렬의 테두리를 1차원 리스트로 추출하는 방법**을 구현하지 못했다.
  - 이후 내가 사용했던 동일한 네 방향 반복문에서 값을 이동시키는 대신 `append()`하면 테두리를 추출할 수 있다는 것을 알게 되었다.

```python
border.append(matrix[x1][y])
```

  - Python의 `deque.rotate()`도 새롭게 알게 되었다.

```python
border.rotate(1)   # 오른쪽으로 한 칸 회전
border.rotate(-1)  # 왼쪽으로 한 칸 회전
```

  - 이번 문제는 접근 자체를 하지 못한 것이 아니라, 생각한 방법을 코드로 옮기는 과정에서 막혔다. 앞으로 구현 문제를 더 풀면서 **아이디어를 실제 반복문과 인덱스 처리로 변환하는 능력**을 더 키워야겠다.
