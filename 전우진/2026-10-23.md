### 문제 설명
- 문제 URL : [디스크 컨트롤러](https://school.programmers.co.kr/learn/courses/30/lessons/42627)

### 접근 방식 : 1. 정렬과 우선순위 큐
- 왜 이 방식으로 풀었나?
  - 현재 도착한 작업 중 소요시간이 가장 짧은 작업을 선택해야 한다.
  - 요청 시각순 정렬로 도착 순서를 관리하고, 우선순위 큐로 대기 작업의 처리 순서를 관리한다.
  - 전체 작업을 소요시간순으로 정렬하면 아직 도착하지 않은 작업을 먼저 처리할 수 있다.

- 전체 수도코드
  1. jobs를 요청 시각순으로 정렬하고 소요시간순 우선순위 큐를 만든다.
  2. 현재 시각까지 요청된 작업을 큐에 모두 넣는다.
  3. 큐가 비었다면 다음 요청 시각으로 이동한다.
  4. 큐에서 작업 하나를 꺼내 소요시간만큼 현재 시각을 증가시킨다.
  5. 종료 시각 - 요청 시각을 누적하고, 모든 작업을 처리할 때까지 반복한다.
  6. 누적 반환 시간을 작업 수로 나눈 정수 값을 반환한다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: O(N log N). 정렬과 각 작업의 큐 삽입 및 삭제가 필요하다.
  - 공간복잡도: O(N). 대기 큐에 최대 N개의 작업을 저장한다.

### 회고
- 잘한 점 : 요청 순서와 처리 우선순위를 분리하고, 대기 작업이 없을 때 다음 요청 시각으로 바로 이동했다.
- 개선할 점 : 처음에는 도착 여부를 고려하지 않고 전체 작업을 소요시간순으로 정렬했다. 우선순위를 정하기 전에 현재 선택 가능한 후보부터 확인해야 한다.
- 구현 중 수정한 점 : 반복 조건을 `processed <= jobs.length`로 작성해 마지막 작업 이후 배열 범위를 벗어났다. 모든 작업을 처리하면 종료하도록 `<`로 수정했다.
