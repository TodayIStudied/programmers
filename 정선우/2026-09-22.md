### 접근 방식 : Dictionary + 문자열 처리
- 처음에는 `split()`을 이용해 각 기록을 `state`, `user_id`, `nickname`으로 분리했다.
- `user_id`를 key로 두고 상태와 닉네임을 함께 저장하려 했지만, 상태는 여러 번 발생하는 기록이고 닉네임은 최종 값만 필요하다는 차이가 있었다.
- 따라서 `user_id`를 기준으로 최종 닉네임을 Dictionary에 저장하고, 기록을 다시 확인하면서 최종 닉네임으로 출력하도록 구현했다.
- 시간복잡도
  - `record`를 두 번 순회하므로 `O(N)`이다.

### 회고
- 몇 번만에 성공했는지 : 4회

- 잘한 점 :
  - 문제를 보고 먼저 `split()`으로 문자열을 분리해야 한다는 것을 생각했다.
  - `user_id`를 Dictionary의 key로 사용해 닉네임을 관리하는 방향을 잡았다.
  - 상태와 닉네임의 역할이 다르다는 것을 확인하면서 자료를 분리해서 관리하는 방법을 이해했다.

- 개선할 점 :
  - 처음에는 다음처럼 한 Dictionary에 상태와 닉네임을 모두 저장하려 했다.

```python
user_dict[user_id] = [state, nickname]
```

  - 하지만 `Enter`, `Leave`는 여러 번 발생하므로 하나의 값으로 저장하면 이전 기록이 덮어써진다.
  - 데이터를 저장하기 전에 **어떤 값은 누적 기록이 필요한지, 어떤 값은 최신 값만 필요한지** 먼저 구분해야겠다.

- 새로 배운 점 :
  - 서로 다른 자료구조에 저장하더라도 공통된 `user_id`를 이용해 데이터를 연결할 수 있다.
  - 다른 사람의 풀이를 보면서 새로운 `history` 리스트를 만들지 않고 **기존 `record` 자체를 다시 순회해서 기록으로 활용할 수 있다는 것**을 배웠다.

```python
printer = {
    'Enter': '님이 들어왔습니다.',
    'Leave': '님이 나갔습니다.'
}

printer[state]
```

- 느낀 점 :
  - 이번 문제에서는 코드 자체보다 **데이터마다 역할을 나누고 공통 ID로 연결하는 방식**을 이해한 것이 가장 도움이 되었다.
