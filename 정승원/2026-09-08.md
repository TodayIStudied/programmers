### 접근 방식 : 1. 반복문을 이용한 풀이.
- 여러 반복문을 이용한 풀이.
- 하나씩 전부 관찰하면서 가능한지 확인하고 리스트에 넣으려고 함.
- 시간 초과 메모리 초과.

### 접근 방식 : 2. 백트래킹을 이용한 조합 탐색
- 왜 이 방식으로 풀었나?
  - 1번으로 풀리지 않아 고민.
  - 현재 선택한 선분들과 겹치지 않는 선분만 추가하면서 가능한 조합을 탐색했다.
  - `st`에는 현재 선택한 선분들을, `mx`에는 지금까지 찾은 최대 선택 개수를 저장했다.
  - `check(l1, l2)`에서 한 선분의 끝점이 다른 선분의 시작점보다 작을 때만 겹치지 않는다고 판단했다. 끝점이 같은 경우도 겹치는 것으로 처리했다.
  - `check_tlt(l[i], st)`에서 새 후보를 현재 선택한 모든 선분과 비교했다. 하나라도 겹치면 해당 후보를 추가하지 않았다.
  - 선택 가능한 선분은 `st.append(l[i])`로 추가하고 `bt(i + 1)`로 다음 인덱스부터 탐색했다. 인덱스를 증가시켜 같은 선분을 재선택하거나 같은 조합을 순서만 바꾸어 탐색하지 않도록 했다.
  - 재귀 호출이 끝나면 `st.pop()`으로 선택을 취소하고 다른 후보를 탐색했다.
  - 재귀 함수에 진입할 때마다 `mx = max(mx, len(st))`로 최대 개수를 갱신했다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(n × 2ⁿ)**
    - 모든 선분이 서로 겹치지 않는 최악의 경우, 선분의 부분집합을 탐색하게 된다.
    - 후보 선분 하나를 추가할 수 있는지 확인할 때 현재 선택한 선분을 최대 n개 비교한다.
    - 따라서 최악의 시간복잡도는 O(n × 2ⁿ)이다. 선분이 겹치는 경우에는 후보를 일찍 제외하므로 탐색량이 줄어들 수 있다.
  - 공간복잡도: **O(n)**
    - 입력 선분 목록, 현재 선택 목록 `st`, 최대 n단계의 재귀 호출 스택을 사용한다.
    - 모든 조합을 별도의 배열에 저장하지 않고 최대 개수만 유지한다.
