### 접근 방식 : 1. 우선순위 큐 / 최소 힙 (heapq)
- 왜 이 방식으로 풀었나?
  - 매일 들어오는 점수 중 상위 k개를 유지하면서 그중 최솟값(명예의 전당 최하위 점수)을 계속 구해야 하므로 최소 힙(min-heap)이 적합
  - 힙의 크기가 k 미만이면 점수를 바로 `heappush`
  - 힙 크기가 k에 도달한 뒤에는 현재 점수가 힙의 최솟값(`top_k[0]`)보다 클 때만 `heappop` 후 새로 삽입
  - 매일 힙의 루트(`top_k[0]`)를 결과 리스트에 추가
- 시간복잡도, 공간복잡도 관점에서의 성능 비교 
  - 시간복잡도: O(N log K) (`score` 길이 N <= 1,000, 힙 크기 K <= 100이라 연산량 아주 적음)
  - 공간복잡도: O(K) (최대 k개 원소만 힙에 유지)
  - 정확성 테스트 통과 (0.15ms 내외)

### 회고 
- 몇 번만에 성공했는지 : 1번
- 잘한 점 : 매번 리스트를 슬라이싱/정렬하지 않고 최소 힙으로 크기를 k로 제한해 효율적으로 푼 점
- 개선할 점 : `heappop` 후 `heappush` 하는 대신 `heapq.heappushpop`이나 `heapq.heapreplace`를 쓰면 힙 재정렬 과정을 한 번으로 줄일 수 있음
