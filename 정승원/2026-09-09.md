### 문제 설명
- 문제명: 특정 조건에 맞게 K개 중에 1개를 N번 뽑기
- 풀이 URL: [특정 조건에 맞게 K개 중에 1개를 N번 뽑기 — 내 풀이 코드]
(https://github.com/HappyPotatohappy/CodingTest/blob/main/trail4/특정%20조건에%20맞게%20K개%20중에%201개를%20N번%20뽑기/n-permutations-of-k-with-repetition-under-constraint.py)
- 사용 언어: Python
- 1부터 K까지의 숫자 중 하나를 N번 선택하여 만들 수 있는 수열을 출력한다.
- 같은 숫자가 3번 이상 연속해서 등장하는 수열은 제외하고, 가능한 수열을 사전순으로 출력한다.

### 접근 방식 : 1. 백트래킹과 조건문, 반복문 - 틀린 풀이
- 왜 이 방식으로 풀었나?
  - 각 자리에서 1부터 K까지 하나씩 선택하며 가능한 수열을 탐색해야 하므로 백트래킹을 사용했다.
  - 추가 되는 숫자가 몇 번 추가되는지 카운트해서 3번이면 넘어가려고 했음.
  - 생각의 방향은 맞았을 수 있는데 논리의 흐름(?)이 복잡했고 특이 어떤 조건에서 0으로 다시 초기화하고 검사를 반복하고 등등 어려움이 많았고 문제를 풀어내지 못 했다. 

### 접근 방식 : 2. 백트래킹과 가지치기
- 왜 이 방식으로 풀었나?
  - 각 자리에서 1부터 K까지 하나씩 선택하며 가능한 수열을 탐색해야 하므로 백트래킹을 사용했다.
  - `arr`에는 현재까지 선택한 숫자를 저장하고, `bt(loc)`의 `loc`은 다음에 선택할 자리 번호를 나타낸다.
  - `bt(1)`부터 시작하여 숫자를 하나 선택할 때마다 `bt(loc + 1)`을 호출한다.
  - `loc == n + 1`이면 N개의 숫자를 모두 선택한 상태이므로 `print(*arr)`로 출력하고 돌아간다.

- 조건을 검사하는 방법1 -> 이것이 핵심.
  - 후보 숫자 `i`를 `arr.append(i)`로 추가한 뒤, 길이가 3 이상이면 마지막 세 숫자를 비교한다.
  - `arr[-1] == arr[-2] == arr[-3]`이면 같은 숫자가 3번 연속된 것이므로, 방금 넣은 숫자를 `pop()`하고 `continue`로 다음 후보를 확인한다.
  - 조건을 만족하면 다음 자리를 재귀적으로 탐색하고, 돌아온 뒤 `arr.pop()`으로 선택을 취소한다.
  - 앞부분은 이미 조건을 통과한 상태이므로 새 숫자를 추가할 때 마지막 세 숫자만 검사하면 된다.
  - 조건을 위반한 수열은 숫자를 더 붙여도 유효해질 수 없으므로, 완성하기 전에 탐색을 중단할 수 있다.

- 조건을 검사하는 방법2 -> 생각만 해보고 비 효율적이라 사용하지는 않음.
  - 가능한 모든 경우를 일단 저장.
  - 그리고 그 모든 경우들을 검사하면서 한 숫자가 3번 연속으로 나오는 경우를 제외한다.


- 출력 순서
  - 각 자리에서 `range(1, k + 1)`로 작은 숫자부터 선택한다.
  - 따라서 별도의 정렬 없이 사전순으로 출력된다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: 러프하게 **O(N × Kᴺ)** 
    - 조건 없이 각 자리에서 K개 중 하나를 N번 고르면 수열 후보는 Kᴺ개다.
    - 마지막 세 숫자를 비교하는 조건 검사는 O(1)이다.
    - 수열 하나를 출력하는 데 O(N)이 필요하므로 출력 비용까지 포함한 상한은 O(N × Kᴺ)이다.
    - 실제로는 같은 숫자가 3번 연속되는 순간 이후 탐색을 생략하므로, 방문하는 경우의 수와 출력량이 줄어든다.
  - 공간복잡도: **O(N)** — 출력 결과를 제외한 보조 공간
    - 현재 수열 `arr`에 최대 N개의 숫자를 저장하고, 재귀 호출 스택도 최대 O(N) 깊이를 사용한다.
    - 가능한 수열을 전부 저장하지 않고 완성되는 즉시 출력한다.

### 회고
- 몇 번만에 성공했는지: 3번
- 잘한 점:
  - 수열을 완성한 뒤 검사하지 않고, 선택하는 도중 조건을 검사하여 불필요한 탐색을 줄였다.
  - 마지막 세 숫자만 확인하여 매번 수열 전체를 검사하지 않도록 했다.
  - 조건 위반 시와 재귀 호출 종료 시 모두 `pop()`을 수행하여 다음 후보를 탐색하기 전 상태를 복구했다.
- 개선할 점:
  (AI)
  - 숫자를 추가하기 전에 `len(arr) >= 2 and arr[-1] == arr[-2] == i`를 검사하면, 조건에 맞지 않는 후보를 넣었다가 바로 빼는 과정을 생략할 수 있다.
