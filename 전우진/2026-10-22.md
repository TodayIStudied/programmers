### 접근 방식 : 1. 시뮬레이션과 HashSet

- 왜 이 방식으로 풀었나?
  - 명령 순서대로 한 칸씩 이동하므로 시뮬레이션으로 현재 위치를 갱신함
  - 방문한 좌표가 아니라 지나간 길을 세어야 하므로 출발 좌표와 도착 좌표를 묶어 `HashSet`에 저장함
  - 같은 길을 반대 방향으로 지나가도 중복으로 세지 않도록 정방향과 역방향을 함께 기록함
- 전체 의사코드
  1. `r = 0`, `c = 0`, `count = 0`으로 시작하고 `HashSet<String> visited`를 만듦
  2. `dirs`의 각 명령마다 `dr = 0`, `dc = 0`으로 초기화하고, `U`는 `dr = 1`, `D`는 `dr = -1`, `R`은 `dc = 1`, `L`은 `dc = -1`로 정함
  3. `nr = r + dr`, `nc = c + dc`를 계산하고, 둘 중 하나라도 `-5~5`를 벗어나면 `continue`로 해당 명령을 무시함
  4. 이동 전 출발 좌표로 `forward = r + "," + c + "," + nr + "," + nc`, `backward = nr + "," + nc + "," + r + "," + c`를 만듦
  5. `visited.add(forward)`가 `true`이면 `visited.add(backward)`를 실행하고 `count++` 함. `HashSet.add()`는 새 원소면 `true`, 이미 있는 원소면 `false`를 반환함
  6. 처음 지나가는 길인지와 관계없이 `r += dr`, `c += dc`로 이동함
  7. 모든 명령을 처리한 뒤 `count`를 반환함
- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - `N = dirs.length`, `E`: 격자에서 가능한 무방향 간선 수
  - 기대 시간복잡도 `O(N)`: 명령마다 다음 좌표를 계산하고 해시 집합에 기록함
  - 공간복잡도 `O(min(N, E))`: 서로 다른 길마다 정방향과 역방향 키를 저장함
  - 이 문제의 격자는 `11 x 11`이고 무방향 간선은 `220`개이므로 최대 `440`개의 키를 저장함. 고정된 격자 범위에서는 공간복잡도의 상한이 `O(1)`임
  - 일반적인 해시 분포와 좌표 문자열 길이가 상수라는 가정임

### 회고

- 잘한 점 : 좌표 방문 여부로는 같은 점에 다른 길로 도착하는 경우를 구분할 수 없다는 문제를 짚고, 두 좌표를 묶어 길을 기록하도록 수정했음
- 개선할 점 : 길을 기록한 뒤 현재 좌표를 갱신하고, 이미 지나간 길이어도 이동해야 한다는 처리 순서를 먼저 정리할 필요가 있었음
