### 접근 방식 : Dictionary + Sliding Window
- 왜 이 방식으로 풀었나?
  - 회원가입 후 10일 동안 원하는 상품을 모두 구매할 수 있는 날짜를 찾아야 하므로 10개의 고정된 구간을 하나의 Window로 생각했다.
  - 첫 10개의 상품 개수를 Dictionary에 저장한 뒤, Window를 한 칸씩 이동시키면서 빠지는 상품은 `-1`, 새로 들어오는 상품은 `+1` 하도록 접근했다.
  - 현재 Window의 상품 개수가 원하는 상품과 일치하면 `answer`를 증가시켰다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 매번 10개의 상품을 처음부터 다시 계산하지 않고 기존 Window를 재사용했다.
  - Window가 이동할 때 빠지는 값과 들어오는 값만 갱신하는 방식으로 구현했다.

### 회고
- 몇 번만에 성공했는지 : 1회

- 잘한 점 :
  - 문제를 읽고 바로 **10개를 하나의 Window로 두고 한 칸씩 이동시키는 방법**을 생각했다.
  - Window 전체를 매번 다시 계산하는 것이 아니라 `빠지는 값 -1`, `들어오는 값 +1`로 갱신하는 방식을 떠올렸다.
  - 최근 반복해서 사용한 Dictionary의 빈도 계산 방법을 이번 문제에서도 자연스럽게 적용할 수 있었다.
  - 문제를 보고 필요한 자료구조와 처리 방식을 이전보다 빠르게 떠올릴 수 있었다.

- 개선할 점 :
  - 이번에 생각한 방식이 `Sliding Window`라는 알고리즘이라는 것을 새롭게 알게 되었다.
  - Dictionary의 value가 `0`이 되어도 key가 자동으로 삭제되는 것은 아니므로 직접 삭제해야 한다는 것을 알게 되었다.

```python
if window[out_item] == 0:
    del window[out_item]
```

  - 앞으로 **연속된 일정 범위만 계속 확인하는 문제**가 나오면 Sliding Window를 떠올려봐야겠다.
