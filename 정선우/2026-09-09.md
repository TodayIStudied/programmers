### 접근 방식 : Stack + Queue
- 왜 이 방식으로 풀었나?
  - 문자열을 회전시켜야 하므로 `deque`를 사용했다.
  - 각 문자열이 올바른 괄호인지 확인하기 위해 Stack을 사용했다.
  - 여는 괄호는 Stack에 넣고, 닫는 괄호가 나오면 Stack의 가장 위에 있는 괄호와 짝이 맞는지 확인했다.
  - 한 번 검사한 뒤 `rotate(-1)`을 이용해 문자열을 왼쪽으로 회전시켰다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 문자열을 `N`번 회전하고 매번 `N`개의 문자를 검사하므로 시간복잡도 : `O(N²)`
  - Stack에 최악의 경우 문자열 전체가 들어갈 수 있으므로 공간복잡도 : `O(N)`

### 회고
- 몇 번만에 성공했는지 : 여러 번 수정 후 **처음으로 풀이 로직을 혼자 완성하여 성공**

- 잘한 점 :
  - 지금까지 문제를 풀면서 처음으로 문제 접근부터 구현, 오류 확인, 수정, 최종 통과까지 스스로 해결했다.
  - 문제를 읽고 `Queue + Stack + Dictionary`를 사용해야겠다는 구조를 직접 설계했다.
  - 괄호의 짝을 Dictionary로 만들어 Stack의 마지막 값과 현재 문자를 비교하는 방법을 생각했다.
  - 이전 문제에서 배운 `deque.rotate()`를 이번 문제에서는 스스로 떠올려 실제 풀이에 활용했다.
  - 처음 작성한 코드가 실패했을 때 처음부터 다시 작성하지 않고, 직접 실행 흐름을 확인하면서 `pop()` / `popleft()`, Queue 생성 위치 등의 문제를 하나씩 수정했다.

- 개선할 점 :
  - Dictionary의 Key가 여는 괄호뿐인데 닫는 괄호를 Key로 조회하면서 `KeyError`가 발생했다. 앞으로 `dict[key]`를 사용할 때 해당 값이 실제 Key로 존재할 수 있는지 먼저 확인해야겠다.
  - 실패 여부를 표시하기 위해 Stack에 `"1"`을 넣는 방식으로 해결했는데, 이후에는 `valid = True/False`와 같은 Boolean 변수를 사용하는 방법도 고려할 수 있다.
