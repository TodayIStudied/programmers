## 등장하지 않는 문자열의 길이

### 문제 설명

- 문제명: 등장하지 않는 문자열의 길이
- 문제 URL: [코드트리 — 등장하지 않는 문자열의 길이](https://www.codetree.ai/trails/complete/curated-cards/challenge-length-of-string-that-does-not-appear)
- 풀이 URL: [등장하지 않는 문자열의 길이 — 내 풀이 코드](https://github.com/HappyPotatohappy/CodingTest/blob/7bf2d7af4bb46d0254782cde2c09b346e99c85aa/trail2/등장하지%20않는%20문자열의%20길이/length-of-string-that-does-not-appear.py)
- 사용 언어: Python
- 길이가 N인 문자열에서, 길이가 같은 연속 부분 문자열들을 뽑았을 때 중복이 생기지 않는 최소 길이를 구한다.
- 즉, 길이 K인 부분 문자열이 서로 다른 시작 위치에서 두 번 이상 등장하지 않도록 하는 가장 작은 K를 출력한다.
- 서로 겹치는 구간도 비교 대상에 포함한다. 여기서 다루는 것은 문자를 연속으로 잘라 만든 **부분 문자열**이다.

### 접근 방식 : 1. 길이별 부분 문자열 생성 + 모든 쌍 비교를 통한 완전탐색

- 왜 이 방식으로 풀었나?
  - 정답은 부분 문자열의 길이이므로, 길이를 1부터 N까지 하나씩 가정할 수 있다.
  - 각 길이에서 가능한 부분 문자열을 모두 만들고, 서로 같은 문자열이 있는지 직접 비교한다.
  - 짧은 길이부터 확인하므로 처음으로 중복이 없는 길이를 찾으면 그 값이 최솟값이다.

- 부분 문자열을 만드는 방법
  - `i`를 현재 검사할 부분 문자열의 길이로 사용한다.
  - 시작 위치 `j`를 `0`부터 `N - i`까지 이동시키며 `str[j:j+i]`를 `cand`에 저장한다.
  - 길이가 i인 부분 문자열은 총 `N - i + 1`개 만들어진다.
  - 시작 위치를 한 칸씩 이동하므로 서로 겹치는 부분 문자열도 빠짐없이 포함된다.

- 중복 여부를 검사하는 방법
  - 처음에는 `is_ans = True`로 설정한다.
  - `cand`의 인덱스 `k`, `l`을 이중 반복문으로 순회한다.
  - `k == l`이면 같은 위치에서 뽑은 문자열을 자기 자신과 비교하는 것이므로 건너뛴다.
  - 서로 다른 위치의 문자열이 같다면 `is_ans = False`로 바꾸고 안쪽 반복문을 종료한다.
  - 비교가 끝난 뒤에도 `is_ans`가 참이면 현재 길이 i를 출력하고 길이 탐색을 종료한다.

- 예시로 확인하기: `ABABA` (설명용 예시)
  - 길이 1: `A`, `B`, `A`, `B`, `A` → 중복이 있다.
  - 길이 2: `AB`, `BA`, `AB`, `BA` → 중복이 있다.
  - 길이 3: `ABA`, `BAB`, `ABA` → `ABA`가 중복된다. 두 구간이 겹쳐도 중복으로 판단한다.
  - 길이 4: `ABAB`, `BABA` → 서로 다르므로 정답은 **4**이다.

- 구현에서 주의할 점
  - `range(N - i + 1)`의 `+1`을 빠뜨리면 마지막 시작 위치를 검사하지 못한다.
  - 원본 주석에는 “부분 수열”이라고 적혀 있지만, 슬라이싱으로 연속된 구간을 추출하므로 정확한 표현은 “부분 문자열”이다.
  - 중복을 발견했을 때의 `break`는 `l` 반복문만 종료한다. `is_ans`는 계속 거짓이므로 정답에는 영향이 없지만, 나머지 `k`에 대한 불필요한 비교가 이어진다.
  - 길이가 N이면 부분 문자열이 전체 문자열 하나뿐이므로 중복이 없다. 따라서 늦어도 N에서는 정답을 찾는다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도 상한: **O(N⁴)**
    - 길이 i에서 부분 문자열의 개수를 `M = N - i + 1`이라고 하면, 문자열을 잘라 저장하는 데 O(Mi)가 든다.
    - 쌍 비교는 최대 O(M²)번 수행하며, 길이 i인 문자열의 동등 비교 한 번은 최악의 경우 O(i)가 든다.
    - 이를 모든 길이에 대해 합한 `Σ i(N - i + 1)²`은 O(N⁴)이다. 이는 조기 종료의 이득을 제외한 보수적인 상한이다.
    - 문자열 비교를 O(1)로 단순화하면 O(N³)으로 계산되지만, Python 문자열의 실제 비교 비용까지 고려하면 위와 같은 상한을 얻는다.
  - 공간복잡도: **O(N²)**
    - 한 길이에서 최대 `N - i + 1`개의 길이 i인 문자열을 저장하므로 O(i(N - i + 1))의 공간이 필요하다.
    - `cand`는 길이마다 새로 만들기 때문에 모든 길이의 부분 문자열을 동시에 보관하지 않는다.
  - 개선 방법과 비교
    - `set`에 부분 문자열을 넣으며 이미 등장한 문자열인지 확인하면, 모든 쌍을 직접 비교하지 않아도 된다.
    - 슬라이싱과 문자열 해싱 비용을 포함하면 전체 기대 시간은 O(N³), 최대 공간은 O(N²)이다. 해시 충돌이 통상적으로 처리된다는 가정의 기대 시간이다.

- 잘한 점:
  - 길이를 작은 값부터 탐색해 처음 조건을 만족하는 길이가 곧 최솟값이 되도록 구성했다.
  - 모든 시작 위치에서 부분 문자열을 생성해 겹치는 구간의 중복도 검사했다.
  - 자기 자신과의 비교를 제외해 같은 위치를 중복 등장으로 잘못 판단하지 않도록 처리했다.
- 개선할 점 (AI):
  - 변수명 `str`은 Python 내장 타입 이름과 겹치므로 `s`나 `text`로 바꾸면 좋다.
  - 현재는 `(k, l)`과 `(l, k)`를 모두 확인한다. `l`을 `k + 1`부터 순회하면 같은 쌍을 두 번 비교하지 않는다.
  - 중복을 하나라도 찾으면 해당 길이는 정답이 될 수 없으므로, 바깥쪽 비교 반복문도 함께 종료하도록 개선할 수 있다.
  - 중복 여부만 필요하므로 `set`으로 이미 본 부분 문자열을 관리하면 비교 구조가 단순해지고 기대 시간복잡도도 줄어든다.
  - `if is_ans == True:`는 `if is_ans:`로 간결하게 쓸 수 있다.
