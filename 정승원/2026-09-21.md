## 흰검 칠하기

### 문제 설명

- 문제명: 흰검 칠하기
- 풀이 URL: [흰검 칠하기 — 내 풀이 코드](https://github.com/HappyPotatohappy/CodingTest/blob/b52583d1093a18323f9654404a65a23848ba1566/trail2/흰검%20칠하기/painting-white-black.py)
- 사용 언어: Python
- 일직선으로 무한히 나열된 타일 위에서 N개의 명령을 실행한 뒤, 흰색·검은색·회색 타일의 수를 순서대로 구한다.
- `x L`은 현재 위치를 포함해 왼쪽으로 x개의 타일을 흰색으로, `x R`은 현재 위치를 포함해 오른쪽으로 x개의 타일을 검은색으로 칠한다.
- 명령이 끝나면 마지막으로 칠한 타일 위에 선다. 현재 위치도 칠하는 개수에 포함하므로 실제 이동 거리는 **x − 1**이다.
- 타일은 마지막으로 칠한 색으로 바뀌지만, 흰색과 검은색으로 **각각 두 번 이상** 칠해지면 회색이 되어 이후에는 색이 바뀌지 않는다. 두 색을 칠한 순서는 상관없다.
- 입력 범위는 `1 ≤ N ≤ 1,000`, `1 ≤ x ≤ 100`이다.

### 접근 방식 : 1. 좌표 오프셋을 이용한 배열 시뮬레이션 + 색깔별 누적 횟수 관리

- 왜 이 방식으로 풀었나?
  - 각 명령이 칠하는 타일은 최대 100개이고 명령도 최대 1,000개이므로, 해당 구간의 타일을 하나씩 갱신해도 칠하기 반복은 최대 100,000번이다.
  - 마지막 색만 저장하면 회색이 되는 조건을 판단할 수 없다. 따라서 현재 색과 함께 흰색·검은색으로 칠한 횟수를 따로 저장한다.
  - 명령을 입력 순서대로 실행하면 덧칠되는 순서와 현재 위치의 변화를 그대로 반영할 수 있다.

- 음수 좌표를 배열 인덱스로 바꾸는 방법
  - `mx_num = 100 * 1000`으로 두고, 시작 위치를 `start = mx_num`으로 설정한다.
  - 실제 시작 좌표를 0이라고 보면 배열 인덱스 100,000이 좌표 0에 해당한다. 왼쪽으로 움직여도 충분한 여유가 있어 음수 인덱스를 사용하지 않는다.
  - `vw`, `vb`, `ans`는 각각 길이가 `2 * mx_num`, 즉 200,000인 배열이다.
  - 한 명령의 이동 거리는 최대 99이므로 시작점에서 벗어나는 거리는 최대 `1,000 × 99 = 99,000`이다. 따라서 접근하는 인덱스는 1,000부터 199,000 사이에 있어 현재 배열 범위 안에 들어간다.

- 타일마다 저장하는 정보
  - `vw[i]`: i번 타일이 회색으로 확정되기 전까지 흰색으로 칠해진 횟수다.
  - `vb[i]`: i번 타일이 회색으로 확정되기 전까지 검은색으로 칠해진 횟수다.
  - `ans[i]`: 현재 타일의 상태다. `''`는 아직 칠하지 않음, `'w'`는 흰색, `'b'`는 검은색, `'g'`는 회색이다.
  - 회색 타일은 이후 갱신을 건너뛰므로 `vw`, `vb`가 그 뒤의 모든 칠하기 횟수까지 기록하지는 않는다. 최종 색을 구하는 데에는 추가 횟수가 필요하지 않다.

- 방향에 따라 칠할 구간을 정하는 방법
  - 현재 위치를 p, 칠할 타일 수를 x라고 하면 왼쪽 명령의 구간은 **[p − x + 1, p]**이다.
  - 코드에서는 `d = -1`, `col = "w"`, `st = start + d * int(num) + 1`, `ed = start`로 설정한다.
  - 오른쪽 명령의 구간은 **[p, p + x − 1]**이다.
  - 코드에서는 `d = 1`, `col = "b"`, `st = start`, `ed = start + d * int(num) - 1`로 설정한다.
  - 두 경우 모두 `ed - st + 1 == x`이므로 `range(st, ed + 1)`로 정확히 x개의 타일을 칠한다.
  - 왼쪽으로 이동하는 명령도 배열은 작은 인덱스부터 순회한다. 한 명령 안에서는 서로 다른 타일을 같은 색으로 한 번씩 칠하므로, 구간 내부의 처리 순서가 결과에 영향을 주지 않는다.
  - 칠하기가 끝나면 왼쪽 명령은 `start = st`, 오른쪽 명령은 `start = ed`로 바꿔 마지막 타일 위치를 다음 명령의 시작점으로 삼는다.
  - 특히 `x == 1`이면 현재 타일만 칠하고 위치는 바뀌지 않는다.

- 색깔을 갱신하고 회색을 유지하는 방법
  - `ans[i] == "g"`이면 `continue`로 건너뛴다. 한 번 회색이 된 타일은 다시 흰색이나 검은색으로 바뀌지 않는다.
  - 회색이 아닌 타일은 먼저 `ans[i] = col`로 이번에 칠한 색을 반영한다.
  - 흰색이면 `vw[i]`, 검은색이면 `vb[i]`를 1 늘린다.
  - 그다음 `vw[i] >= 2 and vb[i] >= 2`를 검사해 두 조건을 모두 만족하면 `ans[i] = "g"`로 바꾼다.
  - 예를 들어 같은 타일을 `흰색 → 흰색 → 검은색 → 검은색 → 흰색` 순서로 칠하면 네 번째에 회색이 되고, 다섯 번째에도 회색을 유지한다. 이 예시는 설명용이다.
  - 한 색으로만 네 번 칠하거나 흰색 세 번·검은색 한 번 칠한 경우에는 회색이 되지 않는다. 총횟수보다 **각 색의 횟수**가 중요하다.

- 최종 개수를 구하는 방법
  - 모든 명령을 실행한 뒤 `ans` 전체를 한 번 순회한다.
  - `'w'`, `'b'`, `'g'`를 각각 `cnt_w`, `cnt_b`, `cnt_g`에 더한다.
  - 한 번도 칠하지 않은 `''`는 어떤 개수에도 포함하지 않는다.
  - `print(cnt_w, cnt_b, cnt_g)`로 문제에서 요구한 순서대로 출력한다.

- 예제에서 확인할 부분
  - 예제 1의 `4 R → 5 L → 7 R → 4 L`을 처리하면 흰색 2개, 검은색 3개, 회색 2개가 되어 `2 3 2`를 출력한다.
  - 예제 2의 `1 L → 1 L → 1 R → 2 R → 1 L`에서는 처음 세 명령 동안 위치가 바뀌지 않는다. 네 번째 명령에서 시작 타일이 회색으로 바뀌고, 마지막 명령이 오른쪽 타일을 흰색으로 바꾸므로 `1 0 1`을 출력한다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - N을 명령 수, X를 한 명령에서 칠할 수 있는 최대 타일 수, M을 배열의 길이라고 하자. 현재 코드는 `X ≤ 100`, `M = 200,000`이다.
  - 시간복잡도: **O(NX + M)**
    - 세 배열 초기화와 마지막 색깔 집계에 O(M)이 필요하다.
    - 명령 처리 비용은 각 명령의 칠하기 개수의 합인 O(Σx)이며, 최악에는 O(NX)이다.
    - 회색 타일을 `continue`로 건너뛰어도 해당 인덱스 방문은 계속하므로, 최악의 시간복잡도 자체가 줄어드는 것은 아니다.
  - 공간복잡도: **O(N + M)**
    - 입력 명령을 `commands`에 저장하고 `x`, `dir`에도 값을 추가하므로 O(N) 공간을 사용한다.
    - `vw`, `vb`, `ans` 세 배열의 공간은 O(M)이다. 배열이 세 개여도 점근적 복잡도는 O(M)이다.
  - 딕셔너리에 방문한 타일만 저장하면, 실제 방문한 서로 다른 타일 수를 U라고 할 때 상태 저장 공간을 O(U)로 줄일 수 있다. 대신 해시 조회 비용이 추가된다. 현재처럼 좌표 범위가 충분히 작고 상한이 명확할 때는 배열 방식이 단순하다.
  - 누적 합이나 차분 배열만으로 최종 색을 바로 구하기는 어렵다. 흰색·검은색 횟수뿐 아니라 회색이 아닌 타일의 마지막 칠하기 색도 필요하기 때문이다. 현재 입력 범위에서는 직접 시뮬레이션으로 필요한 상태를 함께 갱신하는 방식이 적합하다.
