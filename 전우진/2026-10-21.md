### 문제 설명

- 문제 URL : [충돌위험 찾기](https://school.programmers.co.kr/learn/courses/30/lessons/340211)

### 접근 방식 : 1. 시뮬레이션 + HashMap

- 왜 이 방식으로 풀었나?
  - 동시 이동 방식에서 로봇별 시간과 좌표를 기록하는 방식으로 바꿔 경유지와 퇴장을 개별 처리하고, 겹치는 위치를 집계하도록 정리했음
- 전체 수도코드
  1. `HashMap<String, Integer>`를 만들고, 로봇마다 출발 위치를 `time = 0`에 한 번 기록함
  2. 다음 경유지까지 행 우선, 열 후순위로 한 칸씩 이동하고 `time++` 함
  3. 위치를 기록할 때 `"시간,행,열"`을 키로 `records.put(key, records.getOrDefault(key, 0) + 1)`을 실행함
  4. 경유지에서 시간 초기화나 중복 기록 없이 이어가고, 최종 도착 시각까지 기록한 뒤 종료함
  5. `records.values()`에서 2 이상인 항목마다 1을 더함. 3대 이상이 모여도 위험 상황은 1번으로 셈
- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - `S`: 출발 위치를 포함한 전체 기록 수, `U`: 고유한 시간과 좌표 조합의 수
  - 평균 시간복잡도 `O(S)`: 이동 기록 누적 후 집계값을 순회함
  - 공간복잡도 `O(U)`, 최악 `O(S)`: 시간과 좌표 조합별 방문 수를 저장함
  - 문자열 키 길이를 상수로 보고, 일반적인 해시 분포를 가정함

### 회고

- 몇 번만에 성공했는지 : 2회
- 잘한 점 : 행을 먼저 이동한 뒤 열을 이동하는 규칙을 경로 기록에 반영했음
- 개선할 점 : 코딩 전에 시간, 위치, 경유지의 기록 단위를 명확히 정할 필요가 있었음
