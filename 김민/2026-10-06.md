### 접근 방식 : 유니온 파인드 변형 (경로 압축 + 해시맵)

- k가 최대 10^12라 배열로 방 상태를 관리할 수 없음 → 실제로 배정된 방만 unordered_map에 기록
- parent[x] = "x번 방이 찼을 때 다음으로 확인할 방 번호"로 정의. 처음 배정되면 parent[x] = x + 1
- 이미 찬 방이면 parent를 따라가며 빈 방을 찾고, 돌아오면서 경로 압축으로 지나온 방들이 찾은 빈 방을 바로 가리키게 함 → 같은 구간을 다시 찾을 때 거의 O(1)

### 회고

- 몇 번만에 성공했는지 : 1번
- 잘한 점 : "다음 빈 방"을 찾는 문제를 유니온 파인드로 바꿔 생각했고, 큰 k는 해시맵으로 해결함
- 개선할 점 : 재귀로 Find를 짜서 요청이 내림차순으로 들어오면 재귀 깊이가 최대 20만까지 가 스택 오버플로 위험이 있음. 반복문으로 바꾸고, 경로를 압축할 때 이미 찬 방 r 대신 r + 1을 가리키게 하면 탐색 한 번을 더 아낄 수 있음. count()와 [] 대신 find()를 써서 해시 조회를 한 번으로 줄이고, reserve()로 rehash도 줄이기
