### 접근 방식 : 순차 탐색 + 중복 확인
- 왜 이 방식으로 풀었나?
  - 처음에는 참가자별로 단어를 나누기 위해 `n`개의 리스트를 가진 2차원 리스트를 만들려고 했다.
  - 하지만 탈락자를 구하기 위해 참가자별 단어를 따로 저장할 필요가 없다고 판단하여, 이전에 등장한 단어만 `used_words`에 저장하는 방식으로 변경했다.
  - 현재 단어가 이전에 등장했는지 확인하고, 이전 단어의 마지막 문자와 현재 단어의 첫 문자를 비교했다.
  - 탈락한 위치 `i`를 `n`으로 나눈 몫과 나머지를 이용하여 참가자 번호와 차례를 계산했다.


- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 현재 풀이에서 `used_words`는 List이므로 `in`을 이용한 중복 탐색은 `O(N)`이 걸린다.
  - 이를 모든 단어에서 반복하므로 최악의 경우 전체 시간복잡도는 `O(N²)`이다.
  - 중복 확인용 자료구조를 `set`으로 변경하면 평균 `O(1)`에 존재 여부를 확인할 수 있어 전체를 평균 `O(N)`으로 개선할 수 있다.

### 회고
- 몇 번만에 성공했는지 : 3번

- 잘한 점 :
  - 이전에 나온 단어를 별도의 `used_words`에 저장하여 중복을 검사하는 방법을 스스로 생각했다.
  - 탈락자의 위치를 별도의 참가자별 배열 없이 몫과 나머지만으로 계산했다.

- 개선할 점 :
  - 처음에는 문제에 필요한 정보보다 많은 정보를 저장하려고 했다. 앞으로는 자료구조를 만들기 전에 **실제로 어떤 값을 저장해야 정답을 구할 수 있는지** 먼저 생각해봐야겠다.
  - Python에서 2차원 리스트를 생성하는 방법과 `while words`, `range(n)` 등의 기본 문법이 아직 익숙하지 않은 부분이 있었다.
  - 중복 확인을 위해 List를 사용했는데, 중복 여부만 확인하는 경우에는 `set`이 더 적합하다는 것을 새롭게 알게 되었다.

### 오늘 새롭게 익힌 개념

#### Set
중복을 허용하지 않으며 특정 값의 존재 여부를 평균 `O(1)`에 확인할 수 있다.

```python
used_words = set()
used_words.add(words[i])
```

### 느낀 점
- 처음에는 참가자마다 리스트를 따로 만들어야 한다고 생각해서 문제를 필요 이상으로 복잡하게 접근했다.
- 직접 구현하다 보니 결국 필요한 것은 **이전에 나온 단어인지, 앞 단어와 연결되는지, 현재 인덱스가 몇 번째 사람의 몇 번째 차례인지** 세 가지뿐이라는 것을 알게 되었다.
- 특히 복잡하게 시작한 풀이를 중간에 버리고 더 간단한 구조로 다시 생각해서 혼자 정답까지 도달했다는 점이 좋았다.
