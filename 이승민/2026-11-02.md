### 문제 설명

- 풀이 URL : [체육복](https://github.com/sm-dev-enjoy/algorithm-exp/tree/main/%ED%94%84%EB%A1%9C%EA%B7%B8%EB%9E%98%EB%A8%B8%EC%8A%A4/lv1/42862.%E2%80%85%EC%B2%B4%EC%9C%A1%EB%B3%B5)
- 문제 요약 : 전체 학생 수 `n`, 체육복을 도난당한 학생 번호 배열 `lost`, 여벌 체육복을 가져온 학생 번호 배열 `reserve`가 주어질 때, 바로 앞번호나 뒷번호 학생에게만 체육복을 빌려주어 체육수업을 들을 수 있는 학생 수의 최댓값을 구하는 문제입니다.

### 접근 방식 : 1. 배열 필터링과 Set을 이용한 대여 가능자 집계 (초기 풀이)

- 왜 이 방식으로 풀었나?
  - 여벌 체육복을 가져온 학생이 도난당했을 경우 다른 학생에게 빌려줄 수 없으므로, 먼저 `lost`와 `reserve` 양쪽에 동시에 포함된 학생을 `filter`로 제거했습니다.
  - 이후 도난당한 학생(`newlost`)을 순회하며 `newreserve`에 `번호 - 1` 또는 `번호 + 1`이 있으면 `livearray`에 추가하고, `Set`으로 중복을 제거해 빌려줄 수 있는 인원수를 계산했습니다.
- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 도난당한 학생 수를 $L$, 여벌 학생 수를 $R$이라 할 때 중복 제거 및 탐색 과정에서 `includes`가 반복 호출되어 시간복잡도는 $O(L \times R)$, 공간복잡도는 보조 배열과 `Set`을 사용하여 $O(L + R)$입니다.
  - 성능 측정 결과 : 메모리 `33.5 MB`, 시간 `3.29 ms` (디버깅용 `console.log` 출력 비용 포함)

### 접근 방식 : 2. 정렬 후 앞번호 우선 대여하는 탐욕법(Greedy) (개선 풀이)

- 왜 이 방식으로 풀었나?
  - 번호순으로 정렬된 상태에서 여벌이 있는 학생이 앞번호(`newreserve[i] - 1`) 학생에게 먼저 빌려주어야 뒷번호 학생이 다음 여벌 학생에게 빌릴 기회를 최대한 보존할 수 있습니다.
  - `newlost`와 `newreserve`를 정렬한 뒤, 여벌 학생을 순회하며 앞번호 학생이 `newlost`에 있으면 먼저 빌려주고(`newlost`에서 제거), 없을 때만 뒷번호(`newreserve[i] + 1`) 학생에게 빌려주도록 탐욕법(Greedy)으로 개선했습니다.
  - 마지막에 전체 학생 수 `n`에서 끝까지 빌리지 못한 `newlost.length`를 빼서 정답을 반환했습니다.
- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 정렬에 $O(L \log L + R \log R)$, 대여 순회에 $O(L \times R)$이 소요되며 전체 학생 수 $n \le 30$으로 입력 크기가 작아 매우 빠르게 동작합니다. 공간복잡도는 $O(L + R)$입니다.
  - 성능 측정 결과 : 메모리 `33.4 MB`, 시간 `0.09 ms` (초기 풀이 대비 실행 시간 `3.29 ms`에서 `0.09 ms`로 단축)

### 회고

- 몇 번만에 성공했는지 : 3번 (초기 통과 후 탐욕법 정렬 및 리팩터링 2회)
- 잘한 점 :
  - 여벌 체육복이 있는 학생이 도난당한 예외 케이스를 루프 진입 전에 `filter` 전처리로 먼저 제거해 조건 분기를 단순화했습니다.
  - 앞번호를 우선 탐색하는 탐욕법과 불필요한 배열 제거를 통해 실행 시간을 `3.29 ms`에서 `0.09 ms`로 개선했습니다.
- 개선할 점 :
  - JavaScript의 기본 `Array.prototype.sort()`는 요소를 문자열(유니코드 코드 포인트) 기준으로 정렬하므로 학생 번호가 두 자리 수(10 이상)가 되면 숫자 크기순으로 정렬되지 않습니다. `sort((a, b) => a - b)`를 명시해 숫자 오름차순 정렬을 보장해야 합니다.
  - 매 반복마다 `includes`와 `filter`로 배열을 재할당하는 대신 `Set`의 `has()`와 `delete()`를 사용하면 탐색과 제거를 $O(1)$에 처리할 수 있습니다.
