# 프로그래머스 Lv.2 — 무인도 여행

### 문제 설명
- 풀이 URL : [무인도 여행](https://github.com/sunoo2468/codingTestPre/blob/main/Python/%ED%94%84%EB%A1%9C%EA%B7%B8%EB%9E%98%EB%A8%B8%EC%8A%A4/2/154540.%E2%80%85%EB%AC%B4%EC%9D%B8%EB%8F%84%E2%80%85%EC%97%AC%ED%96%89/%EB%AC%B4%EC%9D%B8%EB%8F%84%E2%80%85%EC%97%AC%ED%96%89.py)
- 난이도 : Lv.2
- 알고리즘 : DFS(스택) + 그래프 기반

### 접근 방식 : 스택 기반 DFS

1. 지도의 모든 좌표를 순회하면서 `X`가 아니고 방문하지 않은 칸을 찾는다.
2. 상하좌우로 이동하면서 지도 범위 안에 있고, `X`가 아니며 방문하지 않은 칸을 스택에 추가한다.
   - 중복 탐색을 방지하기 위해 스택에 넣는 시점에 방문 처리한다.
3. 하나의 DFS가 종료되면 연결된 무인도의 식량 합계를 `answer`에 저장한다.
   -전체 지도를 탐색할 때까지 반복한다.
4. 각 무인도의 식량 합계를 오름차순으로 정렬한다.
   - 무인도가 존재하지 않으면 `[-1]`을 반환한다.

- 시간복잡도 : `O(N × M + K log K)` — 전체 지도 탐색 및 무인도별 식량 합계 정렬 (`K`는 무인도 개수)
- 공간복잡도 : `O(N × M)` — 방문 배열과 DFS 스택

### 회고

- **몇 번 만에 성공했는지** : 2회

- **잘한 점**
  - 문제의 데이터를 그래프 탐색 구조로 해석했다. 2차원 지도에서 상하좌우로 연결된 칸을 하나의 무인도로 처리하고, 탐색 단위별로 식량 합계를 계산하는 방식으로 문제를 해결했다.
  - 오류의 원인을 알고리즘과 실행 환경 관점에서 구분했다. 재귀 DFS의 탐색 논리는 유지하면서도, 깊은 재귀 호출이 Python의 실행 제한에 영향을 줄 수 있다는 점을 이해하고 반복 DFS로 변경했다.
  - 재귀 호출 스택 대신 명시적인 스택을 사용하여 탐색을 수행하고, 재귀 깊이 제한으로 인한 런타임 에러를 방지했다.

- **개선할 점**
  - DFS를 구현할 때 입력 크기와 최악의 연결 구조를 고려해 재귀 방식과 반복 방식 중 적절한 구현을 선택해야 한다.
  - 실제 실행 환경에서 발생할 수 있는 예외와 제한 사항까지 확인해야 한다.

- **새로 배운 점**
  - DFS는 재귀 함수뿐 아니라 `stack`과 `while`문을 이용해서도 구현할 수 있다.
  - Python은 재귀 호출 깊이에 제한이 있어, 연결된 노드가 많은 경우 `RecursionError`가 발생할 수 있다.
  - 2차원 배열에서 상하좌우 탐색을 구현할 때 방향 배열을 활용하면 중복 코드를 줄일 수 있다.

- **느낀 점**
  - 그리디 학습을 마치고 DFS 문제를 다시 풀면서, 알고리즘의 구현뿐 아니라 실행 과정에서 발생하는 문제도 고려해야 한다는 점을 배웠다.
  - 처음에는 재귀 DFS로 접근했지만 런타임 에러가 발생했고, 스택 기반 반복 DFS로 변경하면서 문제를 해결할 수 있었다.
  - 같은 DFS 알고리즘이라도 구현 방식에 따라 코드 안정서의 차이가 컸다. 짧은 코드여도 입력 규모, 자료구조, 실행 환경의 제약까지 고려해야 함을 배웠다.
