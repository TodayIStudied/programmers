## 악수와 전염병의 상관관계 2

### 문제 설명

- 문제명: 악수와 전염병의 상관관계 2
- 풀이 URL: [악수와 전염병의 상관관계 2 — 내 풀이 코드](https://github.com/HappyPotatohappy/CodingTest/blob/eba10bb2d9e862001b84505d1338183f60185a77/trail2/악수와%20전염병의%20상관관계%202/correlation-between-shaking-hands-and-infectious-diseases2.py)
- 사용 언어: Python
- N명 중 처음 감염된 사람 P와 감염자가 전염시킬 수 있는 악수 횟수 K가 주어진다.
- T개의 악수 기록을 시간순으로 처리한 뒤, 각 사람의 최종 감염 여부를 1번부터 N번까지 이어 붙여 출력한다.
- 감염된 사람은 감염 후 처음 K번의 악수에서만 상대에게 병을 전염시킬 수 있다. 감염자끼리 악수해도 각자의 악수 횟수는 소모된다.

### 접근 방식 : 1. 시간순 정렬 + 감염 상태와 남은 악수 횟수 시뮬레이션

- 왜 이 방식으로 풀었나?
  - 같은 두 사람이 악수하더라도 언제 만났는지에 따라 감염 여부와 남은 전염 기회가 달라진다.
  - 따라서 `(시간, 사람 1, 사람 2)` 형태의 기록을 시간순으로 정렬하고, 악수 하나마다 상태를 갱신한다.
  - `ans[i]`는 i번 사람의 감염 여부, `remain[i]`는 감염된 i번 사람에게 남은 전염 가능한 악수 횟수다.

- 초기 상태를 설정하는 방법
  - 길이가 `N + 1`인 배열 두 개를 만들어 사람 번호를 그대로 인덱스로 사용한다.
  - 최초 감염자 P는 `ans[P] = 1`, `remain[P] = K`로 설정한다.
  - 다른 사람은 아직 감염되지 않았으므로 두 배열의 값이 모두 0이다.

- 악수 한 건을 처리하는 방법
  - `hand.sort(key=lambda x: x[0])`로 기록을 시간순으로 정렬한다.
  - 양쪽 모두 이미 감염된 경우에는 서로 새로 감염시킬 대상이 없지만, 악수는 했으므로 `remain`을 각각 1 줄인다.
  - 한쪽만 감염되어 있고 그 사람의 `remain`이 0보다 크면 상대를 감염시킨다. 새 감염자의 `remain`은 K로 설정하고, 기존 감염자의 `remain`은 1 줄인다.
  - 감염자의 `remain`이 0 이하라면 더 이상 전염시키지 않는다. 아직 감염되지 않은 사람의 남은 횟수는 소모하지 않는다.
  - 모든 기록을 처리한 뒤 `ans[1:]`을 순서대로 출력한다.

- 구현에서 주의할 점
  - 두 감염자가 악수할 때는 남은 횟수가 이미 0이어도 코드상 1을 더 빼므로 음수가 될 수 있다. 전염 가능 여부를 `remain > 0`으로 검사해 결과에는 영향을 주지 않는다.
  - 새로운 감염자의 K회는 감염 이후의 악수에 적용된다. 이번 악수에서 소모하는 횟수는 이미 감염된 사람의 횟수다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(T log T + N)**
    - T개의 악수 기록을 정렬하는 데 O(T log T), 기록을 한 번 순회하는 데 O(T), 상태 배열을 만들고 출력하는 데 O(N)이 든다.
  - 공간복잡도: **O(T + N)**
    - 악수 기록 T개와 사람별 상태 배열 두 개를 저장한다. 정렬 과정의 추가 공간을 포함해도 O(T + N)이다.
  - 시간순으로 입력된다는 보장이 없다면 정렬이 필요하다. 기록이 이미 시간순임이 보장된다면 정렬 없이 O(T + N)에 시뮬레이션할 수 있다.

### 회고

- 잘한 점:
  - 감염 여부와 남은 전염 기회를 별도 배열로 관리해 조건을 분리했다.
  - 악수 기록을 먼저 정렬해 감염 전파의 시간 순서를 반영했다.
  - 감염자끼리 악수하는 경우에도 각자의 횟수를 차감하는 조건을 처리했다.
- 개선할 점 (AI):
  - `ans`와 `remain`을 각각 `infected`, `remaining_handshakes`처럼 이름 붙이면 배열의 의미가 더 분명하다.
  - 이미 감염된 두 사람의 횟수는 `max(0, remain[i] - 1)`로 0 아래로 내려가지 않게 관리할 수 있다. 현재 결과에는 차이가 없지만 상태의 의미를 유지하기 쉽다.
  - `hand.sort(key=lambda x: x[0])`는 튜플의 첫 요소가 시간이라면 `hand.sort()`로도 같은 순서로 처리할 수 있다. 다만 같은 시간의 기록에 대한 별도 규칙이 있다면 그 규칙을 먼저 확인해야 한다.
