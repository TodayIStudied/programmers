# 기능개발

## 문제 정보

* 플랫폼: Programmers
* 난이도: Level 2
* 문제 번호: 42586
* 사용 언어: Java
* 분류: Queue, 구현

## 문제 요약

각 기능의 현재 진행도 `progresses`와 하루 작업 속도 `speeds`가 주어진다.

각 기능은 100%가 되면 배포할 수 있지만, 뒤의 기능이 먼저 완료되더라도 앞의 기능이 완료될 때까지 배포할 수 없다.

따라서 각 배포 시점마다 몇 개의 기능이 함께 배포되는지를 배열로 반환해야 한다.

예를 들어

```text
progresses = [93, 30, 55]
speeds     = [1, 30, 5]
```

각 기능이 완료되기까지 걸리는 날짜는

```text
[7, 3, 9]
```

이다.

두 번째 기능은 3일 만에 완료되지만 첫 번째 기능이 7일 걸리므로 함께 7일째 배포된다.

따라서 결과는

```text
[2, 1]
```

이다.

## 문제 접근

먼저 각 기능이 완료되기까지 걸리는 일수를 구한다.

필요한 작업량은

```text
100 - 현재 진행도
```

이고 이를 하루 작업 속도로 나누면 완료까지 필요한 날짜를 구할 수 있다.

단, 나누어떨어지지 않는 경우 하루가 더 필요하므로 올림해야 한다.

```java
int days = (int) Math.ceil(
    (double) (100 - progresses[i]) / speeds[i]
);
```

계산한 날짜는 Queue에 순서대로 저장한다.

```text
[7, 3, 9]
```

Queue의 맨 앞 기능은 항상 현재 배포 묶음의 기준이 된다.

첫 번째 기능의 완료일이 `7`이라면 뒤의 기능 중 완료일이 `7` 이하인 기능들은 함께 배포할 수 있다.

```text
7 → 기준

3 <= 7 → 함께 배포
9 <= 7 → 불가능
```

따라서 첫 번째 배포 묶음은 2개가 된다.

이후 남아 있는 `9`를 새로운 기준으로 다음 배포 묶음을 처리한다.

## 전체 코드

```java
import java.util.*;

class Solution {
    public int[] solution(int[] progresses, int[] speeds) {

        Queue<Integer> queue = new LinkedList<>();
        List<Integer> result = new ArrayList<>();

        // 각 기능이 완료되기까지 걸리는 일수 계산
        for (int i = 0; i < progresses.length; i++) {

            int days = (int) Math.ceil(
                (double) (100 - progresses[i]) / speeds[i]
            );

            queue.offer(days);
        }

        // Queue가 빌 때까지 배포 묶음 처리
        while (!queue.isEmpty()) {

            // 현재 배포 묶음의 기준이 되는 기능
            int releaseDay = queue.poll();

            // 기준 기능 자체도 배포되므로 1부터 시작
            int count = 1;

            // 뒤의 기능이 기준 기능보다 빠르거나 같은 날 완료되면 함께 배포
            while (!queue.isEmpty() && queue.peek() <= releaseDay) {
                queue.poll();
                count++;
            }

            // 이번 배포 묶음의 기능 개수 저장
            result.add(count);
        }

        // List<Integer>를 int[]로 변환
        int[] answer = new int[result.size()];

        for (int i = 0; i < result.size(); i++) {
            answer[i] = result.get(i);
        }

        return answer;
    }
}
```

## Queue

Queue는 먼저 들어온 값이 먼저 나오는 FIFO 구조의 자료구조이다.

```text
FIFO
First In First Out
```

예를 들어

```text
[7, 3, 9]
 ↑
가장 먼저 들어온 7이 가장 먼저 처리됨
```

이번 문제는 기능을 앞에서부터 순서대로 배포해야 하므로 Queue와 잘 맞는다.

### Queue 생성

```java
Queue<Integer> queue = new LinkedList<>();
```

### 값 추가

```java
queue.offer(value);
```

Queue의 뒤에 값을 추가한다.

### 맨 앞 값 확인

```java
queue.peek();
```

맨 앞 값을 확인하지만 제거하지는 않는다.

### 맨 앞 값 꺼내기

```java
queue.poll();
```

맨 앞 값을 가져오면서 Queue에서 제거한다.

### 비어있는지 확인

```java
queue.isEmpty();
```

Queue가 비어있으면 `true`, 값이 존재하면 `false`를 반환한다.

## Queue 동작 과정

완료 날짜가

```text
[7, 3, 9]
```

라고 하면 처음 Queue는 다음과 같다.

```text
[7, 3, 9]
```

첫 번째 기능을 꺼낸다.

```java
int releaseDay = queue.poll();
```

결과:

```text
releaseDay = 7
queue = [3, 9]
```

현재 기준 기능 하나는 이미 배포 대상이므로

```java
int count = 1;
```

로 시작한다.

이후 다음 기능을 확인한다.

```java
queue.peek()
```

현재 값은 `3`이다.

```text
3 <= 7
```

이므로 함께 배포할 수 있다.

```java
queue.poll();
count++;
```

결과:

```text
count = 2
queue = [9]
```

다음 값은 `9`이다.

```text
9 <= 7
```

은 거짓이므로 안쪽 while문을 종료한다.

따라서 첫 번째 배포 결과는

```text
2
```

이다.

이 값을

```java
result.add(count);
```

로 저장한다.

이후 Queue에 `9`가 남아 있으므로 바깥 while문이 다시 실행되고 새로운 배포 묶음을 처리한다.

최종 결과는

```text
[2, 1]
```

이 된다.

## 왜 while문을 사용하는가?

이 문제에서는 한 배포 묶음에 몇 개의 기능이 들어갈지 미리 알 수 없다.

예를 들어

```text
releaseDay = 7

queue = [3, 4, 2, 9]
```

이면

```text
3 <= 7 → 함께 배포
4 <= 7 → 함께 배포
2 <= 7 → 함께 배포
9 <= 7 → 불가능
```

처럼 조건이 만족되는 동안 계속 처리해야 한다.

따라서

```java
while (조건) {
}
```

이 자연스럽다.

일반적으로

```text
반복 횟수가 명확함
→ for

특정 조건이 만족되는 동안 반복
→ while
```

처럼 생각할 수 있다.

## 안쪽 while에도 isEmpty()가 필요한 이유

바깥 while문에서 이미

```java
while (!queue.isEmpty())
```

를 확인했지만, 그 안에서

```java
queue.poll();
```

을 실행한다.

예를 들어 Queue에 값이 하나만 남아 있다면

```text
queue = [9]
```

바깥 while은 실행된다.

하지만

```java
int releaseDay = queue.poll();
```

을 실행한 뒤에는

```text
queue = []
```

가 된다.

따라서 안쪽 while문에서 바로

```java
queue.peek()
```

를 사용하면 Queue가 비어 있는 상태일 수 있다.

그래서

```java
while (!queue.isEmpty() && queue.peek() <= releaseDay)
```

처럼 먼저 Queue가 비어있는지 확인한다.

Java의 `&&`는 왼쪽 조건부터 확인한다.

```java
!queue.isEmpty() && queue.peek() <= releaseDay
```

에서 Queue가 비어 있다면

```text
!queue.isEmpty()
→ false
```

가 되고 뒤의 `queue.peek()`는 실행하지 않는다.

이를 단락 평가(short-circuit evaluation)라고 한다.

## Math.ceil()

나누어떨어지지 않는 작업 날짜는 올림해야 한다.

예를 들어

```text
남은 작업량 = 70
하루 속도 = 30
```

이면 실제로는

```text
70 / 30 = 2.333...
```

이므로 3일이 필요하다.

Java에서는

```java
Math.ceil()
```

을 이용해 올림할 수 있다.

단, 정수끼리 나누면 소수점이 먼저 사라진다.

```java
70 / 30
```

결과:

```text
2
```

따라서 먼저 `double`로 형변환해야 한다.

```java
(double) 70 / 30
```

결과:

```text
2.333...
```

그 후

```java
Math.ceil(2.333...)
```

결과:

```text
3.0
```

마지막으로 다시 `int`로 변환한다.

```java
(int) Math.ceil(...)
```

그래서 최종적으로 다음 코드를 사용했다.

```java
int days = (int) Math.ceil(
    (double) (100 - progresses[i]) / speeds[i]
);
```

## 새롭게 배운 내용

이번 문제에서 처음으로 Queue를 사용했다.

Queue의 핵심 메서드는 다음과 같다.

```java
queue.offer(value);  // 값 넣기
queue.peek();        // 맨 앞 확인
queue.poll();        // 맨 앞 꺼내면서 제거
queue.isEmpty();     // 비어있는지 확인
```

또한 Stack과 Queue의 차이도 알게 되었다.

```text
Stack
→ LIFO
→ 마지막에 들어온 값이 먼저 나감

Queue
→ FIFO
→ 먼저 들어온 값이 먼저 나감
```

기능개발 문제에서는 기능의 배포 순서를 반드시 지켜야 하므로 FIFO 구조의 Queue를 사용할 수 있었다.

또한 반복 횟수가 정해져 있는 경우에는 `for`, 조건이 만족되는 동안 계속 반복해야 하는 경우에는 `while`이 자연스럽다는 것도 배웠다.

## 시간 복잡도

각 기능의 완료 날짜를 계산하면서 한 번 순회한다.

```text
O(N)
```

각 기능은 Queue에 한 번 들어가고 최대 한 번 `poll()`된다.

따라서 Queue 처리 역시 전체적으로

```text
O(N)
```

이다.

최종 배열 변환도 최대 N번 수행한다.

따라서 전체 시간 복잡도는

```text
O(N)
```

이다.

## 공간 복잡도

각 기능의 완료 날짜를 Queue에 저장하므로

```text
O(N)
```

의 추가 공간을 사용한다.

배포 결과를 저장하는 List 또한 최악의 경우 N개의 값을 가질 수 있으므로 전체 추가 공간 복잡도는

```text
O(N)
```

이다.

## 배운 점

처음에는 현재 기능과 바로 다음 기능을 비교하려 했지만, 실제로는 현재 배포 묶음의 첫 번째 기능 완료일을 기준으로 뒤의 기능들을 비교해야 한다는 것을 알게 되었다.

또한 Queue를 사용하면 앞의 기능부터 순서대로 처리하면서 `peek()`으로 다음 기능을 확인하고, 함께 배포 가능한 경우 `poll()`로 제거할 수 있다는 것을 배웠다.

특히

```java
while (!queue.isEmpty() && queue.peek() <= releaseDay)
```

에서 `isEmpty()`가 단순히 중복 확인이 아니라 빈 Queue에서 `peek()`를 호출하지 않도록 보호하는 역할을 한다는 점과 `&&`의 단락 평가도 함께 배웠다.
