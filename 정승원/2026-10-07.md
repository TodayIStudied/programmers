## 전부 겹치는 선분

### 문제 설명

- 문제명: 전부 겹치는 선분
- 문제 URL: [전부 겹치는 선분](https://www.codetree.ai/trails/complete/curated-cards/challenge-overlapping-line-segments)
- 풀이 URL: [내 풀이 코드](https://github.com/HappyPotatohappy/CodingTest/blob/d3137f7d490aff6372ffcc366e4c905cfd379945/trail2/전부%20겹치는%20선분/overlapping-line-segments.py)
- 사용 언어: Python
- 분류: Trail 2 / 케이스별로 나누기 / 겹치는 경우 (난이도: 보통)
- 수직선 위에 n개의 선분 `[x1, x2]`가 주어진다.
- 모든 선분이 동시에 지나는 점이 하나라도 있으면 `Yes`, 없으면 `No`를 출력한다.
- 끝점이 맞닿는 경우도 겹치는 것으로 본다. (`[1, 3]`과 `[3, 5]`는 3에서 겹친다.)

### 접근 방식 : 1. 좌표 범위의 모든 정수 점을 완전탐색

- 왜 이 방식으로 풀었나?
  - 좌표가 1~100 범위의 정수이므로, 각 점마다 그 점을 지나는 선분 수를 세면 된다.
  - 어떤 점을 지나는 선분이 n개라면 그 점이 모든 선분의 공통점이다.
  - 공통 구간이 있다면 그 구간의 왼쪽 끝은 어떤 선분의 시작점이고 정수다. 따라서 정수 점만 검사해도 놓치는 경우가 없다.

- 각 점을 검사하는 방법
  - `zip(*segments)`로 시작점 리스트 `x1`과 끝점 리스트 `x2`를 분리한다.
  - `i`를 1부터 100까지 순회하며 `st <= i <= ed`를 만족하는 선분의 개수 `cnt`를 센다.
  - 등호를 포함한 닫힌 구간 비교이므로 끝점이 맞닿는 경우도 겹침으로 처리된다.
  - `cnt == n`인 점을 찾으면 `is_ans = True`로 두고 바로 `break`한다.

- 예시로 확인하기 (설명용 예시)
  - `[1, 5]`, `[3, 8]`, `[4, 6]` → 4와 5는 세 선분을 모두 지나므로 **Yes**
  - `[1, 3]`, `[4, 6]` → 두 선분을 동시에 지나는 점이 없으므로 **No**
  - `[1, 3]`, `[3, 5]` → 3에서 끝점이 맞닿으므로 **Yes**

- 구현에서 주의할 점
  - 탐색 범위 `range(1, 101)`은 좌표 최댓값 100에 맞춘 상수다. 좌표 범위가 바뀌면 이 값도 바꿔야 한다.
  - 좌표가 실수라면 정수 점만 검사하는 방식은 성립하지 않는다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(C · n)** (C = 좌표 범위 크기, 여기서는 100)
    - 점 C개마다 선분 n개를 모두 확인한다.
  - 공간복잡도: **O(n)**
    - 시작점·끝점 리스트를 저장한다.

### 접근 방식 : 2. 시작점의 최댓값과 끝점의 최솟값 비교 (케이스 분석)

- 왜 이 방식으로 생각했나?
  - 모든 선분의 공통 부분은 `[max(x1), min(x2)]`다. 공통점은 모든 시작점보다 오른쪽이고, 모든 끝점보다 왼쪽에 있어야 하기 때문이다.
  - 따라서 `max(x1) <= min(x2)`이면 공통 구간이 존재하고, 아니면 존재하지 않는다.
  - 점 하나하나를 세지 않고, 두 값만 비교해서 바로 판정한다.

- 예시로 확인하기
  - `[1, 5]`, `[3, 8]`, `[4, 6]` → `max(x1) = 4`, `min(x2) = 5` → 4 ≤ 5이므로 **Yes** (공통 구간 `[4, 5]`)
  - `[1, 3]`, `[4, 6]` → `max(x1) = 4`, `min(x2) = 3` → 4 > 3이므로 **No**

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O(n)**
    - 입력을 한 번 읽으며 최댓값과 최솟값만 갱신한다.
  - 공간복잡도: **O(1)**
    - 선분을 저장하지 않고 입력을 받으면서 바로 갱신하면 변수 두 개면 충분하다.
  - 비교
    - 접근 1은 좌표 범위 C에 의존하므로 범위가 커지거나 좌표가 실수면 쓸 수 없다. 접근 2는 좌표 범위와 무관하다.
    - 이 문제처럼 C = 100이면 두 방식 모두 충분히 빠르다.

### 회고

- 몇 번만에 성공했는지: 1번
- 잘한 점:
  - 좌표 범위가 작다는 점을 이용해, 겹침 조건을 직접 따지지 않고 모든 점을 세는 단순한 방법으로 풀었다.
  - 닫힌 구간 비교(`<=`)로 끝점이 맞닿는 경우까지 정확히 처리했다.
  - 공통점을 찾는 즉시 `break`해 불필요한 검사를 줄였다.
  - 랜덤 입력 생성 코드를 작성해 직접 테스트 데이터를 만들어 봤다.
- 개선할 점 (AI):
  - 판정은 `max(x1) <= min(x2)` 한 줄로 바꿀 수 있다. 좌표 범위에 의존하지 않고 O(n)에 끝난다.
  - 제출 코드에 남은 `import random`과 테스트 생성 주석은 지워서 풀이 코드와 테스트 코드를 분리하는 게 좋다.
  - `is_ans` 플래그 대신 `for ... else` 문이나 판정 함수의 `return`을 쓰면 흐름이 더 간결해진다.
