### 접근 방식 : 진법 변환 + 문자열 인덱싱
- 10진수를 n진수 문자열로 바꾸는 함수 작성 (`%`, `/` 반복 후 `reverse`)
- 10~15는 `A`~`F`로 출력해야 하므로 변환 테이블을 미리 만들어 사용
- 0부터 차례로 n진수로 바꿔 이어 붙여, 게임에서 나오는 전체 숫자열 생성
- 튜브가 말할 숫자는 `p-1`번 인덱스부터 `m` 간격으로 나오므로 `t`개를 골라 정답 구성

### 회고
- 몇 번만에 성공했는지 : 1번
- 잘한 점 : 차례를 직접 돌리지 않고 숫자열 전체를 만든 뒤 `p-1 + m*i` 인덱스로 뽑아서 구현을 단순화함
- 개선할 점 :
  - 변환 함수는 `while (p > 0)` 구조라 0을 넣으면 빈 문자열이 나옴. 시작값을 `"0"`으로 두고 1부터 돌려서 처리했지만, 0 같은 경계값은 따로 확인하는 습관이 필요함
  - 숫자 `t*m`개를 모두 변환했는데, 실제로는 문자열 길이가 `t*m`만 되면 충분함. `while (allcomb.size() < t * m)`으로 바꾸면 불필요한 변환을 줄일 수 있음
  - 변환 테이블은 `string` 배열 대신 `"0123456789ABCDEF"[k]`처럼 문자열 하나에서 인덱싱하면 더 간단함 (배열 크기 17도 실제 원소 16개와 맞지 않음)
