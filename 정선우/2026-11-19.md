### 접근 방식 : 해시 + 이분 탐색

1. `info`의 지원자 정보를 언어, 직군, 경력, 음식, 점수로 분리한다.
2. 네 가지 조건을 각각 실제 값 또는 `-`로 설정하여 총 16개의 조합을 만든다.
3. 조합을 딕셔너리의 키로 사용하고 해당 지원자의 점수를 저장한다.
4. 모든 지원자 정보를 처리한 뒤 각 점수 목록을 오름차순 정렬한다.
5. `query`에서 조건과 기준 점수를 분리한다.
6. `bisect_left()`로 기준 점수 이상인 첫 번째 인덱스를 구한다.
7. 전체 점수 개수에서 해당 인덱스를 빼서 결과에 추가한다.

- 시간복잡도 : `O(N log N + Q log N)` — 각 지원자를 16개 조건으로 전처리하고, 검색마다 이분 탐색을 수행한다.
- 공간복잡도 : `O(N)` — 지원자마다 최대 16개의 점수를 저장한다.

### 회고

- **몇 번 만에 성공했는지** : 5회 후 Gpt (난이도 조절 필요,,)
- **잘한 점** : 반복 검색이 많은 문제에서 전처리와 자료구조 선택이 성능에 미치는 영향을 학습했다.
- **개선할 점** : 완전 탐색의 시간복잡도를 먼저 계산하고, 효율성 테스트를 통과하기 위한 최적화 방법을 스스로 설계하는 연습이 필요하다.
- **새로 배운 점** : `defaultdict(list)`로 조건별 점수를 관리하고, `product()`로 와일드카드 조합을 생성할 수 있다. 또한 `bisect_left()`를 활용하면 정렬된 배열에서 특정 값 이상인 원소의 개수를 빠르게 계산할 수 있다.
- **느낀 점** : 처음에는 각 검색 조건마다 지원자를 확인하면 된다고 생각하기 쉽지만, 데이터가 많아지면 시간복잡도를 고려해야 한다는 점을 알게 되었다. 특히 미리 데이터를 분류하고 정렬해 두면 반복적인 검색을 효율적으로 처리할 수 있다는 점이 인상적이었다.
