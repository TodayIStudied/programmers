### 접근 방식 : DFS + 재귀
- 왜 이 방식으로 풀었나?
  - 처음에는 DFS나 재귀 문제라는 것을 알고 접근한 것은 아니었다.
  - 각 숫자마다 `+` 또는 `-` 두 가지 선택지가 있고, 다음 숫자에서도 동일한 선택을 반복해야 한다고 생각했다.
  - 모든 숫자에 대해 `+/-` 경우를 끝까지 확인해야 하므로 자연스럽게 재귀적인 구조가 만들어졌다.
  - 이후 이 방식이 한 경로를 끝까지 탐색한 뒤 다른 경로로 돌아가는 DFS라는 것을 알게 되었다.

### 새롭게 알게 된 코드와 개념

#### 1. 재귀의 결과를 return으로 위에 전달
처음에는 바깥에 `answer`를 만들고 정답을 찾을 때마다 증가시키는 방식을 생각했다.

```python
answer += 1
```

Python에서는 중첩 함수가 바깥 함수의 변수를 수정하려면 다음과 같이 `nonlocal`을 사용할 수 있다는 것을 알게 되었다.

```python
nonlocal answer
```

하지만 이번 문제는 외부 변수를 직접 수정하지 않고 각 경로의 결과를 반환하는 방법으로도 해결할 수 있었다.

```python
plus = dfs(index + 1, total + numbers[index])
minus = dfs(index + 1, total - numbers[index])

return plus + minus
```

정답인 경로는 `1`, 정답이 아닌 경로는 `0`을 반환하고 이를 위로 올라오면서 모두 더하면 최종 정답이 된다.

#### 2. Call Stack
재귀를 호출할 때 기존 함수의 `index`, `total`이 사라지는 것이 아니라 각각의 함수 호출이 자신의 상태를 가지고 Call Stack에 쌓인다는 것을 알게 되었다.

```text
dfs(0, 0)
  ↓
dfs(1, 1)
  ↓
dfs(2, 3)
  ↓
return
```

아래 재귀가 종료되면 이전 함수의 `index`, `total` 상태로 다시 돌아오기 때문에 직접 값을 원래 상태로 복구할 필요가 없다.

#### 3. DFS의 개념 재정의
이번 문제는 **DFS라는 탐색 방식을 재귀를 이용하여 구현한 것**이다.

```text
DFS
→ 한 경로를 끝까지 탐색한 뒤 돌아와 다른 경로를 탐색하는 탐색 방식
```

#### 5. nonlocal
중첩 함수에서 바깥 함수의 변수를 직접 수정하려면 `nonlocal`을 사용할 수 있다.

```python
def solution():
    answer = 0

    def dfs():
        nonlocal answer
        answer += 1
```

`nonlocal`은 현재 함수에서 새로운 지역변수를 만드는 대신 가장 가까운 바깥 함수의 변수를 사용하겠다는 의미이다.

이번 문제에서는 `nonlocal`을 사용하는 방법보다 재귀의 반환값을 합산하는 방법을 사용했다.

### 시간복잡도, 공간복잡도 관점에서의 성능 비교
- 숫자 하나마다 `+`, `-` 두 가지 경우가 발생한다.
- 숫자가 `N`개라면 확인해야 하는 경우의 수는 `2^N`개이다.
- 시간복잡도 : `O(2^N)`
- 재귀 호출의 최대 깊이는 `N`이므로 Call Stack 기준 공간복잡도 : `O(N)`

- 잘한 점 :
  - 실제 코딩테스트 유형의 재귀 문제를 처음 풀어봤다.
  - 처음부터 재귀나 DFS 문제라는 것을 알고 접근한 것은 아니었지만, 각 숫자에서 `+/-` 두 가지 선택을 하고 다음 숫자에서도 같은 작업을 반복해야 한다고 생각하면서 자연스럽게 재귀적인 풀이 방향을 떠올렸다.
  - 알고리즘의 이름을 먼저 떠올리지는 못했지만 문제의 구조를 보고 필요한 탐색 방법에 접근했다는 점은 좋았다.

- 개선할 점 :
  - 이번 문제는 풀이 방향을 생각한 것에 비해 실제 구현 과정에서는 새롭게 알게 된 코드와 개념이 많았다.
  - 특히 재귀의 종료 조건과 `return`, Call Stack, 재귀 결과를 다시 위로 전달하여 합산하는 방식은 혼자 구현하지 못했다.
  - `nonlocal`을 이용해 외부 변수를 수정하는 방법과, 외부 상태를 수정하지 않고 `return`으로 결과를 전달하는 방법의 차이도 처음 알게 되었다.
  - 앞으로 재귀 문제를 볼 때 단순히 코드를 외우기보다 다음 구조를 먼저 생각해야겠다.

```text
1. 현재 상태는 무엇인가?
2. 다음 단계에서 어떤 선택지가 있는가?
3. 언제 탐색을 종료할 것인가?
4. 종료된 결과를 어떻게 위로 전달할 것인가?
```
- 아직 재귀 코드를 혼자 자유롭게 작성할 수준은 아니기 때문에 비슷한 문제를 추가로 풀면서 Call Stack과 반환값의 흐름에 익숙해져야겠다.
