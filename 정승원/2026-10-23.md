## 각 정점까지의 최단 경로

### 문제 설명

- 문제명: 각 정점까지의 최단 경로
- 문제 URL: [각 정점까지의 최단 경로](https://www.codetree.ai/trails/complete/curated-cards/intro-shortest-path-to-each-vertex)
- 풀이 URL: [내 풀이 코드](https://github.com/HappyPotatohappy/CodingTest/blob/6d5a1211ba9b142ea342e8d15cee69832a6d49c4/trail5/각%20정점까지의%20최단%20경로/shortest-path-to-each-vertex.py)
- 사용 언어: Python
- 분류: Trail 5 / Shortest Path / Dijkstra
- 정점 n개와 가중치가 있는 양방향 간선 m개로 이루어진 그래프와 시작 정점 k가 주어진다.
- k에서 1번부터 n번까지 각 정점으로 가는 최단 거리를 한 줄에 하나씩 출력한다. 갈 수 없는 정점은 -1을 출력한다.

### 접근 방식 : 1. 우선순위 큐(heapq)를 이용한 다익스트라

- 왜 이 방식으로 풀었나?
  - 간선마다 가중치가 달라서 BFS처럼 "먼저 도착한 순서 = 최단 거리"가 성립하지 않는다.
  - 가중치가 모두 0 이상이면 **아직 확정되지 않은 정점 중 거리가 가장 짧은 정점**은 더 짧아질 수 없으므로, 그 정점부터 확정하고 이웃 거리를 갱신하는 다익스트라를 쓸 수 있다.
  - 거리가 가장 짧은 정점을 매번 빠르게 꺼내기 위해 `heapq`를 쓴다.

- 그래프를 만드는 방법
  - `edge_lst[v]`에 `[이웃 정점, 가중치]`를 저장하는 인접 리스트를 만든다.
  - 양방향 간선이므로 `st → ed`와 `ed → st`를 모두 추가한다.

- 다익스트라 진행
  - `dist`를 모두 `INT_MAX`로 두고 `dist[k] = 0`, 힙에 `[0, k]`를 넣고 시작한다.
  - 힙에서 거리가 가장 작은 `[min_dist, min_index]`를 꺼낸다.
  - `min_dist != dist[min_index]`이면 이미 더 짧은 거리로 갱신된 뒤에 남아 있던 **오래된 항목**이므로 건너뛴다.
  - 그렇지 않으면 이웃마다 `dist[min_index] + 가중치`가 기존 거리보다 짧은지 확인하고, 짧으면 갱신한 뒤 힙에 새로 넣는다.
  - 끝까지 `INT_MAX`로 남은 정점은 도달할 수 없으므로 -1로 바꿔 출력한다.


- 구현에서 주의할 점
  - 같은 정점이 힙에 여러 번 들어갈 수 있다. 오래된 항목을 건너뛰지 않으면 이미 확정된 정점의 이웃을 불필요하게 다시 확인한다.
  - 다익스트라는 가중치가 음수인 간선이 있으면 성립하지 않는다.

- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 시간복잡도: **O((n + m) log m)**
    - 간선을 확인할 때마다 갱신이 일어나면 힙에 넣으므로 힙에는 최대 O(m)개가 들어가고, 넣고 빼는 데 각각 O(log m)이 든다.
  - 공간복잡도: **O(n + m)**
    - 인접 리스트 O(m), 거리 배열 O(n), 힙 O(m)을 쓴다.


### 회고

- 몇 번만에 성공했는지: 1번
- 잘한 점:
  - 가중치가 있는 최단 거리라서 BFS가 아니라 다익스트라를 써야 한다는 판단을 주석으로 남겼다.
  - `min_dist != dist[min_index]`로 오래된 힙 항목을 건너뛰어 같은 정점을 여러 번 처리하지 않게 했다.
  - 양방향 간선을 인접 리스트에 양쪽으로 모두 추가했다.
  - 도달할 수 없는 정점을 출력할 때 -1로 바꾸는 경우까지 처리했다.
- 개선할 점 (AI):
  - 간선이 많을 때는 `input()`이 느리다. `input = sys.stdin.readline`을 쓰면 정점 20,000개, 간선 200,000개짜리 랜덤 입력에서 로컬 실행 시간이 0.77초에서 0.62초로 줄었다.
  - `edges`에 간선을 모두 저장한 뒤 인접 리스트를 다시 만드는 대신, 입력을 읽으면서 바로 `edge_lst`에 넣으면 같은 간선을 두 번 저장하지 않아도 된다. 제출 결과 메모리가 76MB였으니 줄여 볼 만하다.
  - 힙과 인접 리스트에 리스트 `[거리, 정점]` 대신 튜플 `(거리, 정점)`을 쓰면 객체 생성 비용이 조금 줄어든다.
  - 출력이 n줄이므로 `print`를 n번 호출하는 대신 -1 변환을 마친 뒤 `print("\n".join(map(str, dist[1:])))`처럼 한 번에 출력하면 더 빠르다.
