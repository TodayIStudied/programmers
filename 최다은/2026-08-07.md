### 문제 설명

- 풀이 URL : [달리기 경주](https://github.com/thisischeese/codingTest/tre)

### 접근 방식 : 1. 완탐 + 자구 (dict)

- 왜 이 방식으로 풀었나?
  - callings 리스트를 결국 한 번은 완탐을 해야 함
  - 완탐을 하는 과정에서 O(1)으로 선수와 선수 순서 조회 및 업데이트가 발생해야 함
  - 이를 위해 dict 2개 미리 정의해서 업데이트하는 완탐 코드 구현
- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 메모리: 85.2 MB, 시간: 537.00 ms

### 접근 방식 : 2. 완탐 + 메모리 효율적 자구

- 왜 이 방식으로 풀었나?
  - 이전 코드 생각해보면 orders를 순서: 선수 이름으로 할 필요 없다. 순서가 곧 idx 가능하니까
  - 따라서 orders를 dict가 아닌 리스트로 만든다.
  - 이렇게 구현하면 메모리 공간도 효율적으로 사용하고 마지막에 결과 반환할 때도 정렬 연산, 리스트 변환 등 필요 없어서 시간 복잡도도 줄일 수 있음
- 시간복잡도, 공간복잡도 관점에서의 성능 비교
  - 메모리: 73.4 MB, 시간: 413.22 ms
  - 굿 더 효율적
