### 접근 방식 : 완전탐색
- 처음에는 `0`이 있다면 절대값이 같은 두 수를 찾거나, 두 수를 더한 뒤 합을 `0`으로 만들어 줄 세 번째 수를 찾는 방법을 생각했다.
- 하지만 세 수의 조합에는 `0`이 반드시 포함되는 것이 아니므로 모든 경우를 처리할 수 없었다.
- 입력 크기가 작기 때문에 세 개의 반복문으로 서로 다른 3명을 모두 선택하여 합이 `0`인지 확인했다.
- `j = i + 1`, `k = j + 1`로 시작하여 같은 사람을 다시 선택하거나 같은 조합을 중복해서 확인하지 않도록 했다.

### 시간복잡도
- 세 명을 선택하기 위해 3중 반복문을 사용하므로 `O(N³)`
- 이 문제는 입력 크기가 작기 때문에 충분히 사용할 수 있다.

### 새롭게 알게 된 점
- 완전탐색은 가능한 경우의 수가 충분히 작다면 모든 경우를 직접 확인하는 단순한 방법도 좋은 풀이가 될 수 있다.
- 조합을 구할 때 `i < j < k`가 되도록 반복문을 구성하면 같은 조합을 중복해서 확인하지 않는다.
- 입력 크기가 커진다면 두 수를 선택한 뒤 `-(a + b)`를 HashMap에서 찾는 방식으로 세 번째 반복문을 줄여 평균 `O(N²)` 풀이도 생각할 수 있다.
- HashMap을 사용할 때는 같은 숫자가 여러 개 존재할 수 있으므로 단순 존재 여부가 아니라 `값 → 개수`를 관리해야 한다.

### 회고
- 처음부터 세 수를 모두 확인하기보다 `a + b`를 구하고 이를 `0`으로 만들어 줄 값을 찾는 방법을 먼저 생각했다.
- 더 빠른 방법을 찾는 것도 중요하지만, 입력 크기를 보고 단순한 완전탐색으로 충분한지 먼저 판단하는 것도 중요하다는 것을 알게 되었다.
- 이번 문제에서는 알고리즘보다 `i, j, k`와 `number[i], number[j], number[k]`를 혼동한 부분을 주의해야겠다.
