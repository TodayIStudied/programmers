### 접근 방식 : 1. 정렬 + zip
- 왜 이 방식으로 풀었나?
  - 단 한 명만 완주하지 못했으므로 두 명단을 정렬하면 같은 위치에 동일한 이름이 와야 함
  - `participant`와 `completion`을 각각 사전순 정렬 후 `zip`으로 묶어 앞에서부터 비교
  - 이름이 일치하지 않는 순간의 참가자(`p`)가 완주하지 못한 사람이므로 즉시 반환
  - 루프가 끝날 때까지 없으면 정렬 명단 맨 끝 사람(`participant[-1]`)이 미완주자
- 시간복잡도, 공간복잡도 관점에서의 성능 비교 
  - 시간복잡도: O(N log N) (참가자 수 N <= 100,000 정렬 후 O(N) 순회)
  - 공간복잡도: O(1) (추가 메모리 없이 기존 리스트 제자리 정렬)
  - 정확성 및 효율성 테스트 통과

### 회고 
- 몇 번만에 성공했는지 : 1번
- 잘한 점 : `zip`을 활용해 인덱스 에러 걱정 없이 두 리스트를 깔끔하게 1:1 비교한 점
- 개선할 점 : 해시(`Counter`)를 사용해 차집합 연산을 하면 정렬 없이 O(N)으로도 해결 가능하므로 데이터가 더 많을 땐 해시 접근도 고려하기
